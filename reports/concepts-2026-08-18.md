## concepts-quiz-002 — is the caller's fee bigger than the caller's gas

4/4 both variants, every run.

**Pre-run price check (2026-08-14):** ETH/USD $1,880.26, mainnet `eth_gasPrice` 0.1065 gwei
(base fee 0.1053 gwei, block 25,754,308). $8,000 × 4% = $320/yr = $0.877/day accrual → 1%
caller fee $0.0088/day; 250,000 gas → $0.050/call; **break-even ≈ 5.7 days**. Squarely inside
the notes' "0.1 gwei / ETH $2,000 → 5–6 days" band, so the task still measured what it was
built to measure and the $8,000 deposit figure did not need to come down.

All six runs put the fee and the caller's gas side by side and derived a break-even interval
rather than answering qualitatively. Only one run of six (no_skill run 2) checked prices live
— one WebSearch plus three WebFetch, landing on ETH ≈ $1,908, close to the live $1,880. The
other five quoted from memory (ETH $1,500–$3,000, gas 3–10 gwei) and still passed, because
expect_2 grades the break-even a run derives from the prices it states, not a fixed interval.

The task's own notes predicted this outcome: "If both variants come back 3/3, this task is
not splitting them — the input supplies every number and telegraphs both halves." It does not
split them.

## Run integrity

Three runs were produced and not counted. Each is recorded here rather than quietly dropped.

| Run | Outcome | Disposition |
| --- | --- | --- |
| goal-001 with_skill (20.8 min, scored 7/7) | ran repo-root `git status`, printing sibling run dirs named `…-no-skill-1`, `…-with-skill-1` — the executor could see it was the with_skill arm of an A/B benchmark | **discarded** on the runner's instruction; replaced by run 4. Expect lines never leaked; `setup`'s leak check held |
| goal-001 with_skill (32.5 min) | killed mid-run | **not graded**, run dir deleted |
| goal-001 no_skill (first attempt, 10.0 min) | killed by the orchestrator's own 10-minute foreground Bash cap | **not graded**, run dir deleted |

Plus three aborted launches that produced no run: `Server error mid-response` (11.5 min,
$1.87), `401 OAuth access token has been revoked` (turn 1), and `529 Overloaded` (turn 1) —
an Opus 5 availability window, not three separate faults.

**Why the 32.5-minute run died.** Not a rate limit and not a duration cap. Claude Code
registers a `process.on("memoryPressure")` reaper for main-session background bash tasks
which kills a task when macOS raises memory pressure **and the user has been idle ≥ 30
minutes** — the guard is `Date.now() - userPresence.lastInteractionTime() < 1800000`, not
task age. The run supplied its own memory pressure (a loop spawning `anvil` and
`node --test`), and it was the only run the runner was away for. Every other run had a user
message land inside it, which resets the timer. Escape hatch:
`CLAUDE_CODE_DISABLE_BG_SHELL_PRESSURE_REAP`.

**Executors modified the eval repo three times.** Workspaces live under `artifacts/` *inside*
this git repo, so `forge install` without `--no-git` walks up, finds the enclosing repo and
registers the workspace's `lib/` dependency as a **submodule at the repo root** — writing
`.gitmodules`, a `160000` index entry and `.git/config` sections (forge-std once,
openzeppelin-contracts twice). Worse, one executor "cleaning up" that mess ran
`rm -rf /Users/…/ethskills-evals/lib`, deleting the harness's own `judge.ts`, `task.ts` and
`types.ts` and breaking `yarn verify` until `git restore` recovered them. All occurrences
were reverted; no committed state was damaged and no graded result was affected. This
corroborates existing open work rather than reporting anything new — see #72 (harness: move
workspaces out of the repo tree) and #66 (fix: isolate eval workspaces); three occurrences in
six runs of one task is evidence for landing them.

**The prescribed canary probes the wrong model.** It runs `claude-haiku-4-5` while executors
run `claude-opus-5`. It is a valid rate-limit check — the five-hour window is shared — but it
returned `"status":"allowed"` moments before Opus 5 refused requests with `529 Overloaded`.
Executor-readiness gating needs a probe on the executor's model.
