## The prior this skill corrects is mostly gone on opus-5

The task set was built against three stale beliefs. Two of them no longer reproduce:

- **`nargo prove` / `nargo verify`.** Zero occurrences as commands in any of the 6 quiz-001 scripts. Every run knew nargo only compiles and executes.
- **Commitment-nullifier linkability.** quiz-003 is 3/3 without the skill, and — the stronger result — goal-001 e1 and e2 pass 3/3 without it too, where linkability is never mentioned in the input. All six goal runs routed the vote through a relayer and scoped the nullifier to the proposal id unprompted. This was the eval's centrepiece and the model applies it on its own.

The third is alive, and the skill fixes it:

- **Poseidon.** No `no_skill` run on goal-001 reached the skill's path. Two of three hashed commitments and nullifiers in-circuit with **keccak256** (`noir-lang/keccak256` as a dependency) — ~30,000 gates against ~600, on a circuit whose members prove in a browser. The third used Poseidon2. All three `with_skill` runs used `poseidon::poseidon::bn254::hash_2`. Filed as [noir-keccak-in-circuit-hash](../mistakes/noir/noir-keccak-in-circuit-hash.yaml), 2/3 vs 0/3 — **and no expect in the suite grades it**, because goal-001 deliberately leaves the hash to quiz-002, and quiz-002 is exactly where the model gets it right. It surfaced only by reading circuits.

Filed as [noir-proving-via-bb-cli-not-noirjs](../mistakes/noir/noir-proving-via-bb-cli-not-noirjs.yaml).

All six runs that instantiated the class ended on the two-arg form. `with-skill-1` tried one-arg once anyway, hit `TypeError: Cannot read properties of undefined (reading 'circuitProve')` at `bb.js/dest/node/barretenberg/backend.js:111`, and fixed it the next turn. Graded inside e4 as the expect says; recorded here separately because it is the one place the skill protects against a live documentation error.

## Skill rot found

Four items, all filed. Two cost runs real turns.

1. **poseidon pinned at `v0.2.6` (L189) does not compile on beta.26.** 6/6 `with_skill` runs across quiz-002 and goal-001 copied the pin, hit `error: Expected type [Field], found type &[_; 0]` in `poseidon/mod.nr:355`, diagnosed it, and re-pinned to `v0.3.0`. 0/6 `no_skill` runs ever saw it — they went straight to `v0.3.0`. One wrote the diagnosis up unprompted. **The clearest negative delta in the benchmark: the skill made runs slower at the thing it exists to make them faster at.** It cost no expect, because every run recovered. [noir-poseidon-tag-v026-uncompilable](../mistakes/noir/noir-poseidon-tag-v026-uncompilable.yaml)

2. **`u1` in every Merkle example (L235, L256, L285, L411, L420).** All three `with_skill` circuits wrote `[bool; MAX_DEPTH]` instead and compiled against `binary-merkle-root-v0.0.2`. Corrected silently in-model, no compile round trip — cheaper than the pin, but the examples are code a reader cannot paste. [noir-u1-merkle-indices-stale](../mistakes/noir/noir-u1-merkle-indices-stale.yaml)

3. **Bare `bbup` (L51-57) fails on nargo >= beta.23.** `bb-versions.json` on aztec-packages `next` maps only to 1.0.0-beta.22, so the lookup resolves null and 404s; the skill also points at `master` while the map lives on `next`. Installed as `bbup -v 5.1.0`. Not exercised by any run — no task installs the toolchain — so it is filed with `n/a` frequency rather than left unrecorded. [noir-bbup-bare-invocation](../mistakes/noir/noir-bbup-bare-invocation.yaml)

4. **Not rot, contrary to the task notes.** Two items goal-001's notes list as known rot did not hold on this pin, and the notes should be corrected:
   - *"the generated verifier's Solidity floor is >=0.8.27 now, not >=0.8.21"* — the generated verifier says `>=0.8.21`, matching SKILL.md L20. Nothing to change.
   - *"zk-kit's binary_merkle_root still wants `[u1; N]`, so it does not compile against current Noir"* — only the skill wants `u1`. The library takes `[bool; N]` and compiles fine; 3/3 `with_skill` runs proved it.

## Harness notes

- **MCP burn did not happen.** Zero `claude mcp add noir-mcp` and zero `/reload-plugins` across all 24 transcripts. quiz-001 and goal-001 both ask runs to record it; the predicted negative delta is not real on this harness, and the `-p --strict-mcp-config` spawn was never tested against it because no run tried.
- **No run consulted live docs.** Zero WebSearch/WebFetch in 24 transcripts. quiz-001's "docs vs memory" question resolves to memory in every case, both variants.
- **`nargo compile` and `forge build` genuinely ran and passed** in all six goal-001 runs — every workspace holds a compiled circuit artifact under `target/` and 39-62 forge artifacts under `out/`. The judge reads code and cannot execute, so this is reported, not graded.
- **The 256KB evidence cap bit once.** `no-skill-1`'s generated verifier is **354,247 bytes** and was dropped from `output/`; what survived into the judge's evidence was that run's 974-byte `MockVerifier.sol`, on a task whose e3 fails any MockVerifier in the deploy path. The judge passed e3 correctly by reading the deploy script, so no verdict was harmed — but the failure mode goal-001's notes predicted is real and observed. The other five verifiers are 103,921 bytes (~101.5KB), comfortably under.
- **The `lib/` caveat did not trigger.** `lib` is in `GENERATED_DIRS` (lib/workspace.ts:17-21) while goal-001's input names only node_modules, target, out and cache — but no run put source under `lib/`, and all six wrote `.gitignore` as asked.
- **User-level config reaches executor workspaces.** 4 of 6 quiz-001 executors read `/Users/liana/.claude/RTK.md` on their first turn. `--setting-sources project` governs settings, not `CLAUDE.md` discovery up the filesystem. It appears in both variants and does not bias the comparison, but the isolation is weaker than the flag suggests.
- **Six goal-001 runs were killed mid-flight** by an orchestrator session restart (`nohup` does not survive a process-group teardown). Per AGENTS.md they were deleted as dead runs, not graded as zeros, and re-seeded with fresh run ids (`2026-08-18T0715*`); the relaunch used `fork` + `setsid` so each executor is its own session leader. Both variants were re-run together, so no table below mixes pre- and post-restart runs.

## Honest read

On opus-5 this skill is no longer teaching the lesson it was written for. The linkability claim — the thing both quiz-003 and goal-001 were built to catch — is applied unprompted, with and without the skill, in every run. What the skill still buys is mechanical currency at the toolchain boundary: which npm stack proves, which hash goes in a circuit, where the Merkle path comes from. That is real (3/3 vs 1/3 on the build task) and it is narrower than the task set assumes.

Three of four tasks in this set can no longer distinguish the variants. The next revision should spend its runs where the failures actually were — the NoirJS boundary and in-circuit hash choice under build pressure — and drop the two quizzes that now pass themselves.
