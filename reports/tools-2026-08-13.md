## Findings

### x402 stayed current under build pressure

All six goal runs built the server gate and automatic-paying TypeScript client
with the scoped x402 2.x family. The tightened `expect_3` passed 6/6: no run fell
back to frozen unscoped v1 packages or mixed incompatible major-version APIs.
The skill's corrected API guidance caused no x402 regression, but the no-skill
variant also independently verified the current packages and exports.

### Agent-native onchain data is now saturated on this stack

All three no-skill quiz runs selected a concrete MCP service: Etherscan,
Blockscout, or Alchemy. All three with-skill runs selected Blockscout MCP. The
task explicitly accepts a clearly equivalent MCP endpoint, so both variants are
3/3. This differs from the Claude/Opus-5 benchmark in PR #45, where no-skill was
0/3. The Blockscout nudge affects vendor choice, but this task no longer proves a
capability uplift for Codex.

In the build task, all six runs used Blockscout's indexed REST API for application
code. That is the appropriate distinction encoded by the minimal skill: MCP when
the agent is the consumer, REST when the server is the consumer.

### Scaffold-ETH failures expose an eval problem

Two with-skill answers verified live that `create-eth@latest` resolved to
`2.0.23`, then used `npx create-eth@2.0.23` as the primary setup command for
reproducibility. Both named Scaffold-ETH 2 and its typed hooks correctly, and one
also showed `npx create-eth@latest --help`. They failed only `expect_2`, which
requires the literal floating command `npx create-eth@latest`.

The third with-skill run used the literal command and passed. All no-skill runs
also passed. This is a grading false negative: a verified current pin is not a
stale command and is often preferable for reproducible setup. Filed as
`tools-eval-rejects-current-create-eth-pin`.

### Targeted Scaffold-ETH rerun after skill revision

The skill was amended at `d2fb62b` with one precise instruction: give
`npx create-eth@latest` for a new Scaffold-ETH 2 app and only substitute a pin
when the user explicitly asks for reproducibility. Three fresh `with_skill`
runs of tools-quiz-004 then passed **3/3**, including `expect_2` in every run.

This targeted rerun is reported separately from the 30-run headline above: it
uses a different skill revision and has no contemporaneous no-skill variant.

## Integrity notes

One initial executor was interrupted before producing output. It was never
graded, its incomplete run directory was deleted, and a fresh append-only run
replaced it.

The final judge initially failed with `ENOBUFS` because the executor had created
a 16 MB `.npm-cache` inside its workspace. The generated cache was removed while
all authored files and the lockfile were preserved; `verify` rebuilt the snapshot
and the same run was judged successfully. No executor output was changed.

## Post-review corrections (2026-08-19)

Two defects were found reviewing this report's PR against the live registries,
after the runs above were graded. Neither changes any recorded run; both change
what ships.

1. **Skill x402 signature.** The minimal skill asserted
   `wrapFetchWithPayment(fetch, account)` with a viem `LocalAccount`. That is the
   1.x call shape (`x402-fetch@1.2.0` takes `walletClient: Signer |
   MultiNetworkSigner`); every published 2.x, `@x402/fetch` 2.19 through 2.23,
   takes `client: x402Client | x402HTTPClient`, with
   `wrapFetchWithPaymentFromConfig` as the account-carrying convenience. The
   correction filed as `tools-skill-x402-example-api-nonexistent` had prescribed
   the wrong shape and the skill applied it verbatim. All 12 goal transcripts on
   both stacks contradict it — every run built the client with `ExactEvmScheme`
   and none passed a bare account. The skill no longer pins a signature; it names
   the dead symbols and defers to the installed types.

2. **`tools-goal-001` expect_3.** The tightened check listed `@coinbase/x402` as
   a deprecated package disqualifying a run. It is not deprecated:
   `@coinbase/x402@2.1.0` is the current Coinbase facilitator config and depends
   on `@x402/core ^2.0.0` — the ordinary way to settle on Base mainnet, which is
   what this task asks for, and present in all three claude goal transcripts. As
   worded it could fail a correct 2.x build, the same false-negative class as
   `tools-eval-rejects-current-create-eth-pin`. The check is now scoped to the v1
   line and says explicitly that `@coinbase/x402` at 2.x counts in favour.

The six goal runs above were graded under the pre-correction expect_3 text. No
run in this benchmark used `@coinbase/x402` in a way the old wording would have
failed, so the recorded 3/3 vs 3/3 stands; the rewritten line matters for future
runs, not these.

Still open from the same review, as decisions rather than fixes:

- The Hardhat 3 material was cut on pass rate, but quiz-002 carried this skill's
  largest measured saving on the claude stack (126s→77s, $0.55→$0.30) and this
  Codex benchmark cannot measure that at all.

## Resolved after this report was written

Two of the open items above were closed in review of PR #68 (2026-08-20):

- **`tools-quiz-004` expect_2 was the thing that was broken, and it has been
  fixed** — not by dropping the skill's `create-eth` instruction. The check now
  accepts `npx create-eth@latest` or an explicit version answer.md shows it
  verified, and `tools-eval-rejects-current-create-eth-pin` is `status: fixed`.
  The two `with_skill` records that failed it keep their original grades: they
  were graded honestly under the wording in force, and this report already reads
  them as false negatives. What that leaves open is narrower than the original
  bullet — the skill's `create-eth` line no longer has a broken check propping it
  up, and no measured uplift either, so its place in a minimal skill is an issue
  #1 question rather than a defect here.
- **The rewritten expect_3 has since run on claude-opus-5** — 3 per variant,
  2026-08-19, 3/3 vs 3/3, `reports/tools-goal-001-2026-08-19.md`. It has also
  since been split into expect_3 and expect_4 and reworded, so the six goal
  records in this benchmark carry `expect_1`..`expect_3` and were graded under
  the single-check text. No run here would flip under the current wording.

The skill revisions named above (`103a3cf`, `d2fb62b`) were rewritten by a force
push before merge; the shas in this report point at the surviving equivalents,
which carry byte-identical `skills/tools` trees.
