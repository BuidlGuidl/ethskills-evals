### Fabrication cross-check (orchestrator-owned; the judge cannot do it)

Every command and every pasted output line in all 6 goal `FINDINGS.md` files was matched against that run's `transcript.md` tool calls and results.

**0 fabricated output lines across all 6 runs.** Every `[FAIL]`/`Suite result`/log line pasted as evidence was really produced by a command the executor really ran.

Command text drifted in 3 runs, though — tidied reconstructions rather than verbatim copies (a combined `--match-path 'test/{A,B,C}.t.sol' -vv 2>&1 | tail -60` re-presented as three clean per-file commands; a `--match-test <name>` that was never issued because the test ran under a broader path; dropped pipes). The reconstructions do reproduce the shown output, so this is presentation drift rather than fabricated evidence — but the prompt explicitly said *verbatim*, so it is filed as `testing-evidence-command-not-verbatim`. Two flagged items turned out to be legitimate: placeholder reproduction instructions (`MAINNET_RPC_URL=https://your-endpoint …`) offered as overrides, not claims.

## Judge isolation — audited, two holes found

Checked empirically after the runs, not assumed from reading `verify.ts`.

**Clean:**

- **The skill never reaches the judge.** `SKILL_INSTALL_DIRS = [".agents", ".claude"]` are matched as directory *names* against every path segment in `snapshotOutput`, so no `SKILL.md` and no `.claude/`/`.agents/` content appears in any `output/` tree. Verified by `find` across all 36 evidence trees: zero hits. The judge cannot tell the variant from the evidence.
- **No executor memory exists to leak.** Each executor ran with `cwd` = its own workspace, so Claude Code keyed it to a unique per-run project dir (131 such dirs on this machine). **None has a `memory/` directory.** Executors were fresh processes with no persistent store, and their unique slugs mean they could not see each other either.
- **All 36 judges made zero tool calls.** Confirmed from the session logs: 36 sessions contain a real judge prompt (`EXPECT CONDITIONS`) and have `"type":"tool_use"` count of exactly 0. No judge read a file, a task spec, or a transcript.

**Holes (neither affected these results, both worth fixing):**

1. **`--setting-sources project` does not suppress user-level memory or global CLAUDE.md.** `verify` spawns the judge with `cwd` = repo root, so it inherits the *orchestrator's* user-scoped context for that project path. Probed directly: the judge-equivalent process reports having the `MEMORY.md` index in context and quotes its note back. Here that note is about an unrelated SE-2 vendoring plan, so it did not touch grading — but a memory note containing eval answers or a "skill X is good" prior would leak straight into every verdict.
2. **The judge is not sandboxed and can read `tasks/`.** Same probe: asked to read `tasks/testing-goal-001.yaml`, it returned expect line 1 verbatim. That file also carries the `notes` block with every planted-bug answer and the accept/reject guidance. Nothing in the judge prompt points it there, and the tool-call audit above shows no judge ever did it — but the capability is one stray instruction away from silently invalidating a benchmark.

Fixes worth making before the next eval: run `verify` with `cwd` outside the repo (or sandbox the judge read-only to a temp dir), and **persist judge stdout** — it is currently parsed for verdicts and discarded, so a judge's reasoning is unauditable after the fact and this whole check had to be reconstructed from Claude Code's own session logs.

## Notes on the fixture that should be corrected

Two claims in `tasks/testing-goal-001.yaml` notes did not hold in these runs:

1. **"Neither publicnode nor drpc serves archive requests."** `no_skill-3` pinned block **21,000,000** against `https://eth.drpc.org` and got a working fork, reproducing the USDT approve revert at that block. Runs 1, 2 and all three `with_skill` runs pinned 25,600,000 on the same endpoint. Archive access on that endpoint is currently fine at these vintages, so quiz-004's real-world failure mode never triggered here.
2. **The fourth, un-planted issue "cannot be evidenced by a command … only by inspection."** `no_skill-3` evidenced it by command: forked mainnet, warped 365 days against the real Aave pool, and printed `aUSDT at supply time : 1000000000` → `after 365 days : 1042571282`, `interest accrued : 42571282`. The notes' reasoning that it needs real interest to accrue over forked time is right; the conclusion that no command can show it is not.

Also worth recording: **all 6 runs pinned their fork block** unprompted, which is quiz-004's content applied without being asked.
