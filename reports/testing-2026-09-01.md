## Goal-task findings

The goal prompt never asks for fuzzing, fork testing, or invariants. Across its six
valid runs, the observed methods were:

| Discipline used for a planted bug | `no_skill` | `with_skill` |
| --- | --- | --- |
| Fuzz test (`testFuzz_` / bounded generated inputs) | 0/3 | 0/3 |
| Stateful invariant test with a handler | 0/3 | 0/3 |
| Mainnet fork against real USDT/Aave | 2/3 | 3/3 |
| Inspection plus targeted unit/property test | 3/3 | 3/3 |

The stale prior only partially held. No run treated 39 green tests or 100% coverage
as proof of safety, and five of six independently chose a fork. But **zero of six**
chose fuzzing or a stateful invariant suite, even after all three with-skill runs
read guidance explicitly saying a value-moving stateful vault needs both. The runs
mostly reasoned to suspected defects first and then wrote one counterexample per
defect. That can evidence a known bug, but it does not search the state/input space
the skill claims models otherwise neglect.

Per planted bug:

- **Unbounded deposit fee:** evidenced in 1/3 no-skill and 2/3 with-skill runs.
  The misses did not show both the 10,000-bps no-shares boundary and the above-bound
  underflow with real command output.
- **Withdrawal-fee accounting drift:** evidenced in 3/3 no-skill and 2/3
  with-skill runs. This is a negative correctness delta: one with-skill report
  discussed adjacent accounting risks but did not prove the planted drift to the
  grading standard.
- **Real-USDT approval incompatibility:** evidenced on a mainnet fork in 2/3
  no-skill and 3/3 with-skill runs. This is the clearest positive skill delta.
- **Do-not-ship plus concrete fixes:** 1/3 no-skill and 3/3 with-skill runs met the
  complete condition.

The unplanted Aave-yield accounting defect appeared repeatedly and was correctly
treated as real, per the task notes.

## Recommendations

The skill should make its action guidance harder to satisfy by inspection alone:

1. In **Fuzz Testing**, add a pre-deploy rule: when an owner-controlled numeric
   parameter feeds value math, write a generated-input test over the accepted domain
   before writing hand-picked regression cases. The current example demonstrates
   syntax, but all three skilled runs still chose known counterexamples.
2. In **Invariant Testing**, require a handler-driven invariant for stateful vault
   sign-off and say why: direct calls can revert vacuously, while targeted unit tests
   do not explore multi-actor sequences. Include calls/reverts statistics and
   `fail_on_revert` guidance.
3. In **Fork Testing**, retain the strong “always” language for quirky tokens; it
   produced the clearest measured benefit. Add the archive-access caveat beside the
   pinned-block example.

For the eval, the five quizzes remain useful regression guards, but the goal task is
the discriminating artifact. Strengthen its grading surface to distinguish discovery
from confirmation: add non-outcome observations (already mined from transcripts) or
a separate task where the defect cannot be cheaply inferred and converted into one
targeted unit test. Also update the stale task note claiming goal `run.diff` is empty;
the isolated git workspace now produces a real diff.
