# Eval report — skill `qa` (claude stack)

**Skill:** `skills/qa` @ `9a129f1` (source: ethskills.com/qa/SKILL.md)
**Executor:** claude, `claude-opus-4-8` — fresh `claude -p` per run, pointed only at `TASK.md`.
**Judge:** claude, `claude-opus-4-8` — blind (`--judge-agent claude --judge-model claude-opus-4-8`), fresh process per run, sees only task input + evidence (diff), never the variant/skill/transcript.
**Runs:** 3 per variant per task; 7 tasks × 2 variants × 3 = **42 executor runs**, all graded.
**Date:** 2026-07-24. Content-only variant (agent decides whether to use the skill); **no trigger line prepended** — trigger-inclusive numbers were not run and would be a separate benchmark.

> **`self_judged: true` on every run.** The framework sets `self_judged` when `judge.agent == executor`; both are `claude` here because AGENTS.md prescribes running executor and judge on one stack (claude→opus). Grading was still independent: a fresh, blind `claude -p` process per run with `--judge-agent`/`--judge-model` passed. This is the intended single-stack setup, disclosed as required.

## Method notes

- **Evidence.** Each workspace was `git init` + baseline-committed after `setup`, then `git reset --mixed <baseline>` before `verify`, so `run.diff` is the net change vs the seed regardless of what the executor did with git (goal-002's prompt invites committing). Quizzes: `run.diff` = the new `answer.md`. Goal-001: `run.diff` = the new `REVIEW.md`. Goal-002: `run.diff` = code changes.
- **Baseline is model + repo AGENTS.md, not bare model.** The `qa-target` template's `CLAUDE.md` does `@AGENTS.md`, so Claude Code auto-injects SE-2's bundled `AGENTS.md` into *every* executor context (it never shows as a Read in the transcript). That AGENTS.md teaches the scaffold write hook, `AddressInput`, and `notification`/`getParsedError` — which is exactly why no_skill reliably catches those three and misses the checklist-only claims AGENTS.md does not carry. The no_skill numbers below are the honest "SE-2 project as it ships" baseline.
- **Two transient judge non-JSON failures** (out of 42) were re-verified identically; no run was self-graded.

## The one apparent negative — qa-quiz-004

no_skill 1/3, with_skill 0/3 looks like a regression but is within noise: **both variants fail the same single check, e2 (the ~2s deep-link delay).** Per-expect: e1 3/3·3/3, **e2 1/3·0/3**, e3 3/3·3/3. Every run gets the ordering right (fire `writeContractAsync` first, deep-link after, don't await) but proposes **~150–300ms**, reasoning it as one WalletConnect relay round-trip — not the checklist's ~2s. The skill states 2s but never triggers in quiz framing, so it can't supply the figure. The lone no_skill pass (no-skill-3) used the *same* ~200–300ms answer the failing runs used — **judge noise on a borderline threshold**, not a real point for the base model.
