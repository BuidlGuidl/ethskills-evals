All 23 valid records carry `self_judged: true`. Executor and judge used the same
single-stack model, but each judgment was a fresh blind process that saw neither
the variant, the skill, nor the transcript.

The external checklist repository was unchanged across the sitting. The main-branch
SHA before the first run and after the last attempt was
`ffe4b670e78e1945bcf275f79d4b7b0481bcff35`. This is distinct from `skill_version`,

four dead run directories and workspaces were deleted, never graded, and excluded
from scores and resource comparisons. The benchmark therefore closes with two valid

## Goal-task findings

The three baseline reports each caught 10 of 11 planted vulnerabilities:

- Runs 1 and 2 missed the transfer-before-effects reentrancy in
  `CollateralVault.withdraw`.
- Run 3 caught that ordering bug but missed `block.number` being used as a clock in
  `LendingMarket.accrueInterest`.
- All three correctly ranked a currently exploitable total-loss control-plane bug
  first and passed the severity check.

Both valid skill reports caught all 11 planted vulnerabilities and passed the
severity check. They also reported real ungraded findings from the task notes,
including repayment dust, deeply underwater liquidation economics, unchecked ERC-20
returns, unsafe feed decimal assumptions, and proxy initialization hazards.

Manual review found **zero false positives** in each of the five valid reports. Some
findings were conditional on future callback-capable, fee-on-transfer, or rebasing
collateral, but the reports labeled those conditions rather than presenting them as
launch exploits against wstETH.

Every valid goal executor ran `forge build` before writing its final report. Foundry's
lint output directly exposed the divide-before-multiply expression and pointed at
unchecked ERC-20 transfers and the unsafe signed-to-unsigned cast. The reports still
had to reason beyond those warnings to establish the missing price freshness check,
the balance-actually-received defect, and their concrete impacts. The compiler thus
handed both variants useful leads for expects 4, 6, and 7; those checks do not measure
pure unaided discovery.

All four valid reports that discussed the clock bug got chain semantics right:
Arbitrum's Solidity `block.number` approximates the L1 block number, so multiplying
its delta by 12 seconds is near-correct only by coincidence and remains an invalid
clock abstraction. They prescribed timestamp-based accrual. The fifth report omitted
the finding rather than stating incorrect semantics.

## Routing and transcript observations

Unlike the prior Claude measurement, Codex invoked the skill in all nine skill-enabled
quiz runs: every transcript opened `.agents/skills/audit/SKILL.md` and fetched at least
one external checklist. This is why the existing activation mistake now carries
stack-specific frequencies instead of a blended rate.

Both valid skill goal runs followed the parallel-specialist phase. Run 1 produced
eight domain outputs (`general`, `precision`, `lending`, `erc20`, `oracles`, `proxies`,
`signatures`, and `chain`) before synthesis. Run 2's normalized transcript records
seven specialist completion waits, although it omits the spawn-call payloads and did
not preserve domain files in the workspace. The prior Claude failure to execute
fan-out was therefore not reproduced on Codex.

No valid run attempted `gh issue create` or any other GitHub write. Every valid goal
workspace had exactly one untracked deliverable before grading: `AUDIT-REPORT.md`.
The skill runs created intermediate domain notes during execution but removed them
before finishing, so no `findings-<domain>.md` reached the judge and all valid grades
remained blind.

## Cost and duration

`yarn run-stats --tasks audit-quiz-001,audit-quiz-002,audit-quiz-003,audit-goal-001 --since 2026-09-02 --runs`
reports every Codex run as having no stats footer. Duration and total tokens exist in
the per-run YAML records, but compliant medians and ranges are **not measured by the
mandated tool**. Copying or aggregating those YAML values by hand would violate the
repository rule that every reported duration or cost number come from `run-stats`.

This is a harness gap: the Codex transcript renderer does not append the footer that
`run-stats` parses, and the statistics script does not report total tokens. Add Codex
footer emission and token aggregation before using this benchmark for a resource-cost
claim. The four deleted non-zero attempts must remain excluded from any future valid-run
resource comparison, though their repeated policy exits should be tracked separately
as executor reliability.

## Recommendations

The measured skill content worked: it closed all three observed baseline gaps and its
central routing behavior executed on Codex. No checklist-content edit is supported by
a mistake that remained in the valid skill arm.

The loader should nevertheless be made operationally safer and more reproducible:

1. Pin the external checklist repository to a commit and fetch immutable URLs. The two
   SHA probes documented what this sitting read, but they do not make later runs
   comparable.
2. Cap routing to the documented 5–8 domains and make specialist output transport
   explicit. One run used eight domain files; the other completion evidence was only
   visible as waits in the normalized transcript.
3. Make the issue-filing phase opt-in and require an explicit repository plus user
   confirmation. It self-skipped correctly here, but an audit skill should not infer
   authorization to mutate GitHub from the presence of a remote.
4. Consider splitting or summarizing the largest checklists. Three consecutive valid
   run attempts were blocked by the cybersecurity classifier while consuming the raw
   vulnerability corpus, preventing the planned third sample.

For the eval, retain the goal's findings-count interpretation and add a machine-readable
field for partial finding scores so reports do not reconstruct 10/11 from expectation
maps. Add transcript support for collaboration spawn events, Codex stats footers, and
total-token medians. Finally, distinguish compiler-assisted findings from unaided review
if expects 4, 6, and 7 are intended to measure the checklist rather than `forge lint`.
