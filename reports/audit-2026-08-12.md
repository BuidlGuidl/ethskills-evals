### The parallel sub-agent phase never fired — not once

Phase 3 of SKILL.md is the skill's headline mechanism: one Opus sub-agent per routed domain, each with the full source plus its checklist, writing `findings-<domain>.md`. **Zero Task-tool calls across all twelve with_skill runs**, including goal-001 run 1, which fetched ten checklists and then worked every one of them inline in its own context.

This is the finding that matters most for this eval. The question posed — *does routing a domain sub-agent per area surface bugs a single careful read misses?* — was never actually put to the test, because the routing happened and the fan-out did not. What got measured is "checklists pulled into one context" versus "no checklists", and on this model those tie at the ceiling.

Filed: `mistakes/audit/audit-subagent-phase-never-fires.yaml`.

An incidental benefit: with no sub-agents, no run wrote `findings-<domain>.md` into a workspace, so nothing leaked the variant to the blind judge. **Every one of the 24 gradings was blind.**

### The three mirrored claims are not stale priors on Opus 5

Each quiz targets a claim the goal task also plants, and no_skill got all three right, three times each, with no lookups at all — 3 tool calls per run, typically read TASK.md, write answer.md:

- **Sequencer uptime (quiz-001):** all three no_skill runs named the Chainlink L2 Sequencer Uptime Feed, required a grace period with the borrower-reaction-time reason, explicitly refused to blame the staleness bound, and scoped the gate to liquidation while leaving top-ups open.
- **`block.number` semantics (quiz-002):** all three got the harder half right — that Arbitrum's `block.number` reports an approximation of the *L1* block number, which is why the 12-second constant coincidentally reconciles there — and worked Base through to a consistent over-accrual figure. None offered a per-chain `SECONDS_PER_BLOCK` as the fix.
- **EIP-712 replay (quiz-003):** all three identified replay, prescribed both a signed nonce and a signed deadline, and flagged the constructor-cached domain separator against a chain split.

On goal-001, all six runs got the Arbitrum `block.number` → L1 semantics right *unprompted*, in a task that only required flagging the clock. no_skill run 2 went further and measured it — a Foundry PoC in `/tmp` warping a year forward and accruing 152 wei on a 10,000 USDC debt.

## Verdict

| Question | Answer |
| --- | --- |
| Did the skill improve pass rate? | No. `12/12 vs 12/12` overall; goal-001 `11/11 findings vs 11/11`. Both arms at ceiling on all four tasks. |
| Did it reduce time/tokens? | No — it increased both. On goal-001, runs that loaded the skill cost 27% more and took 36% longer for identical results. |
| Did it create negative deltas? | Cost and latency only. No accuracy regression: no with_skill run missed a finding a no_skill run caught, and no with_skill run reported a false positive. |
| What mistakes repeated without the skill? | None. no_skill passed every expect in all 12 runs, including the three claims the quizzes were built to catch it on. |
| What mistakes remained with the skill? | `audit-subagent-phase-never-fires` (6/6 runs that loaded it), `audit-skill-not-invoked` (6/12 with_skill runs). Neither is a graded failure; both are visible only in the transcripts. |
| What should change in the skill? | (1) Make Phase 3 spawn the sub-agents it describes, or delete the description and own the inline behaviour — right now the skill's headline mechanism is documentation, not execution. (2) Widen the trigger to incident- and post-mortem-shaped prompts; quiz-002 missed 3/3 and goal-001 run 2 read SKILL.md and proceeded without it. |
| What should change in the eval? | **The eval is the wrong artifact for this model.** All four tasks are ceilinged on Opus 5, so they cannot measure the skill either way. goal-001's eleven planted bugs are each individually well-known and the fixture is 381 lines — a careful single read gets all of them, which is exactly what happened six times. To recover discrimination: (a) make the fixture large enough that context, not knowledge, is the binding constraint — a few thousand lines across a dozen contracts, where per-domain fan-out would actually buy coverage; (b) plant bugs that need cross-contract reasoning rather than single-function pattern-matching; (c) grade coverage-under-budget rather than presence/absence. Failing that, run this suite against a weaker executor, where the skill has something to add. Keep the three quizzes as regression canaries — they are cheap and they document that these claims are no longer stale on frontier models — but stop reading them as skill measurements. |
