**Command sequence** (nargo 1.0.0-beta.26 / bb 5.1.0):

```
nargo compile --force --deny-warnings            → target/age_check.json   (frontend artifact)
bb write_vk           -b … -o target -t evm      → target/vk, vk_hash
bb write_solidity_verifier -k vk  -t evm         → HonkVerifier.sol        (foundry artifact)
# smoke
nargo test; nargo execute                        → target/age_check.gz     (witness from Prover.toml)
bb prove  -b … -w … -k vk -o target -t evm       → target/proof, public_inputs
bb verify -k vk -p proof -i public_inputs -t evm → "Proof verified successfully"
```

The load-bearing detail is `-t evm` on **every** bb call: it selects keccak transcript + ZK, which is what makes proofs Solidity-verifiable. `evm-no-zk` also verifies onchain but doesn't hide the witness — wrong for a privacy app.

**Verified, not guessed.** The toolchain is installed on this machine, so I ran the whole flow against a scratch `circuits/age_check/` (`age >= threshold`, `threshold` public): build.sh runs clean end-to-end, and the emitted `dist/HonkVerifier.sol` + `dist/smoke/proof.hex` verify onchain in foundry (`verify()` → true). Also exercised `SKIP_SMOKE`, `ONLY_SMOKE`, `OPTIMIZED_VERIFIER=1`, and the version-drift abort.

Extras worth knowing: version pinning hard-fails (vk bytes are toolchain-dependent, and the vk is compiled into the deployed contract); a `vk_hash` cross-check catches a stale `.sol` copied over a fresh vk; `dist/build-manifest.txt` ties a deployment to a commit; `dist/smoke/` doubles as a foundry fixture.

On mainnet that ~1.36M gas delta is real money; your call whether to flip the default.
