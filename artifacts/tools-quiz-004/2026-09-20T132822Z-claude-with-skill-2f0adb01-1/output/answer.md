# Fastest path to a full-stack Ethereum app

**Use Scaffold-ETH 2.** It is the one tool that gives you all four of your
requirements — Solidity contract, React frontend with *typed* contract calls,
wallet connect, and a local chain — in a single scaffold, with no wiring work.

Everything below was verified end-to-end on 2026-09-20 (see
[Verification](#verification)). `create-eth` is at **2.0.23**, published
2026-07-30.

## Why this over the alternatives

| Option | Verdict for your deadline |
|---|---|
| **Scaffold-ETH 2** | **Pick this.** Contract + Next.js + Foundry + wagmi/viem + RainbowKit + anvil, pre-wired. Typed contract calls are generated automatically on every deploy. |
| Foundry alone | Great contracts, zero frontend. You'd hand-build wallet connect, ABI plumbing, and typegen. |
| Hardhat 3 alone | Same gap — it's a contract toolchain, not a full stack. |
| Rolling your own Next.js + wagmi + viem | Perfectly valid, but it's a day or two of wiring you don't have this week. |

Scaffold-ETH 2 *is* Foundry + wagmi + viem underneath, so you aren't trading
away power for speed — you can drop to `forge` and `cast` whenever you want.

## Setup commands

Prerequisites: Node.js ≥ 20, Git, and Foundry. Install Foundry if you don't
have it:

```bash
curl -L https://foundry.paradigm.xyz | bash
foundryup
```

Scaffold the project (the project name is a **positional** argument):

```bash
npx create-eth@latest my-dapp -s foundry
cd my-dapp
```

`-s foundry` picks the Solidity framework non-interactively; omit it and you
get an interactive prompt. Use `-s hardhat` if you'd rather have Hardhat 3.
Other flags: `-e <extension>`, `--skip-install`, `-h`.

Then run three commands in **three separate terminals**:

```bash
# Terminal 1 — local chain (anvil, chain ID 31337)
yarn chain

# Terminal 2 — deploy contracts + regenerate TypeScript ABIs
yarn deploy

# Terminal 3 — frontend on http://localhost:3000
yarn start
```

That's the whole loop. `yarn install` runs automatically during scaffolding
unless you passed `--skip-install`.

## Where things live

```
packages/foundry/contracts/YourContract.sol      # your Solidity
packages/foundry/script/DeployYourContract.s.sol # deploy script
packages/foundry/test/YourContract.t.sol         # forge tests
packages/nextjs/app/page.tsx                     # your React frontend
packages/nextjs/scaffold.config.ts               # target networks, keys
packages/nextjs/contracts/deployedContracts.ts   # AUTOGENERATED — don't edit
```

`deployedContracts.ts` is rewritten by `yarn deploy` and is what makes contract
calls typed. Re-run `yarn deploy` after every contract change, or your
frontend types go stale.

## Typed contract calls

This is the payoff. Both hooks infer function names, argument types, and
return types straight from your deployed ABI — a typo in `functionName` is a
compile error, not a runtime one.

**Read:**

```tsx
const { data: greeting } = useScaffoldReadContract({
  contractName: "YourContract",
  functionName: "greeting",
});
```

**Write:**

```tsx
const { writeContractAsync } = useScaffoldWriteContract({
  contractName: "YourContract",
});

await writeContractAsync({
  functionName: "setGreeting",
  args: ["Hello"],
  value: parseEther("0.01"), // optional, for payable functions
});
```

Note: passing the contract name as a bare string
(`useScaffoldWriteContract("YourContract")`) is **deprecated** in this version —
use the object form above.

Other hooks available: `useScaffoldContract`, `useScaffoldEventHistory`,
`useScaffoldWatchContractEvent`, `useDeployedContractInfo`, `useTransactor`.

## Wallet connect

Already wired — RainbowKit 2.2.11 on wagmi 2.19.5 / viem 2.53.1. A burner
wallet is enabled on local networks by default, so you can click through
transactions without MetaMask while developing.

**Before you ship to real users,** replace the shared demo keys. Scaffold-ETH
ships public fallback Alchemy and WalletConnect keys so prototyping works out
of the box; they are rate-limited and shared across every SE-2 user. Create
`packages/nextjs/.env.local`:

```bash
NEXT_PUBLIC_ALCHEMY_API_KEY=your_key            # dashboard.alchemyapi.io
NEXT_PUBLIC_WALLET_CONNECT_PROJECT_ID=your_id   # cloud.walletconnect.com
```

## Two pages you get free

- **`/debug`** — an auto-generated UI for every function on your contracts.
  Use it to exercise the contract before you build any real UI. This will save
  you hours this week.
- **`/blockexplorer`** — a local explorer for your anvil chain.

## Shipping to users

`targetNetworks` in `scaffold.config.ts` defaults to `chains.foundry` (local
only). To go live, change it to your real network and redeploy:

```ts
targetNetworks: [chains.sepolia],   // or chains.base, chains.arbitrum, ...
```

```bash
yarn generate                              # create a deployer keystore
yarn account                               # check its address + balance
yarn deploy --network sepolia              # deploy
yarn verify --network sepolia              # verify on the explorer
yarn vercel                                # ship the frontend
```

Fund the deployer with Sepolia ETH from https://sepolia-faucet.pk910.de/ or
https://www.alchemy.com/faucets. Sepolia (chain ID 11155111) is the current
testnet — Goerli and Rinkeby are dead.

`yarn generate` writes an encrypted keystore rather than a plaintext private
key. Never put a mainnet key in `.env`.

## Useful extras

- **`yarn test`** — runs `forge test` against your contracts.
- **`yarn fork`** — anvil forked off mainnet, for testing against real
  deployed protocols.
- **https://abi.ninja** — paste any verified contract address, get a UI for
  every function. Zero setup, useful when integrating someone else's contract.
- **`cast`** — CLI contract calls, e.g.
  `cast call 0xAddr "balanceOf(address)(uint256)" 0xWallet --rpc-url $RPC`.
- The scaffold ships a `.mcp.json` wired to the Context7 MCP server, plus
  `CLAUDE.md` / `AGENTS.md` and skills for ERC-721, SIWE, and EIP-5792 — so
  coding agents in this repo get current docs automatically.

## Suggested order for the week

1. Write your contract in `packages/foundry/contracts/`, test with `yarn test`.
2. Update `script/DeployYourContract.s.sol`, run `yarn deploy`.
3. Exercise it on `/debug` until the contract behaves.
4. Build the real UI in `packages/nextjs/app/page.tsx` with the typed hooks.
5. Swap in your own API keys, point `targetNetworks` at a live network,
   deploy, verify, `yarn vercel`.
