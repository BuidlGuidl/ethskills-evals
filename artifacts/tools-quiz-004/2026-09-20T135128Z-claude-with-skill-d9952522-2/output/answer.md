# Fastest path: Scaffold-ETH 2 via `create-eth`

One command gives you every item on your list already wired together: a Solidity
contract + Hardhat local chain, a Next.js/React frontend, RainbowKit wallet
connect, and typed (ABI-inferred) contract reads/writes through wagmi + viem.
Writing this stack by hand is a day or two; this is about 5 minutes.

Everything below was verified against the live npm registry and by actually
scaffolding a throwaway project on 2026-09-20.

## Prerequisites

- **Node >= 22.10.0** — the generated project declares this in `engines`; it will
  refuse to install on older Node.
- **Yarn 4** (the scaffold sets `packageManager: yarn@4.13.0`). Easiest route:
  ```bash
  corepack enable
  ```
- Git.

## Setup commands

```bash
# 1. Scaffold (interactive prompts for name + Solidity framework)
npx create-eth@latest

# ...or fully non-interactive:
npx create-eth@latest my-app -s hardhat

cd my-app
```

`create-eth` flags, from its own `--help`:

```
[--skip | --skip-install]
[-s | --solidity-framework]   hardhat | foundry
[-e | --extension]            curated or third-party extension
[-h | --help]
```

If you passed `--skip-install`, run `yarn install && yarn format` now.

Then three terminals:

```bash
# Terminal 1 — local chain (Hardhat EDR node, prefunded accounts)
yarn chain

# Terminal 2 — compile + deploy to the local chain
yarn deploy

# Terminal 3 — frontend at http://localhost:3000
yarn start
```

`yarn deploy` against the local network needs **no** private key or keystore
password — the deploy script short-circuits the encrypted-key prompt when the
target is the local chain. You only need `yarn account:generate` /
`yarn account:import` when you deploy to a public network.

Useful extras: `yarn test` (Hardhat tests), `yarn compile`, `yarn fork`
(mainnet fork), `yarn next:check-types`.

## What you actually get

```
packages/hardhat/contracts/YourContract.sol        <- edit this
packages/hardhat/deploy/00_deploy_your_contract.ts <- deploy script
packages/nextjs/app/                               <- your React pages
packages/nextjs/contracts/deployedContracts.ts     <- AUTO-GENERATED by yarn deploy
packages/nextjs/scaffold.config.ts                 <- target networks, RPC, WC id
```

## The typed-contract-call part

`yarn deploy` regenerates `packages/nextjs/contracts/deployedContracts.ts` from
the compiled artifacts. The scaffold hooks read that file, so contract name,
function names, argument types and return types are all inferred — no manual ABI
imports, no addresses in your components, and a typo in a function name is a
compile error.

Hooks live in `packages/nextjs/hooks/scaffold-eth/`. The two you'll use:

```tsx
"use client";

import { useScaffoldReadContract, useScaffoldWriteContract } from "~~/hooks/scaffold-eth";

export function Greeting() {
  // read — `greeting` is typed as string, function name is checked against the ABI
  const { data: greeting } = useScaffoldReadContract({
    contractName: "YourContract",
    functionName: "greeting",
  });

  // write — args tuple is typed from the ABI
  const { writeContractAsync, isMining } = useScaffoldWriteContract({
    contractName: "YourContract",
  });

  return (
    <button
      disabled={isMining}
      onClick={() =>
        writeContractAsync({
          functionName: "setGreeting",
          args: ["gm"],
          value: 0n,
        })
      }
    >
      {greeting}
    </button>
  );
}
```

Notes that will save you time:
- `useScaffoldReadContract` sets `watch: true` by default — it re-reads on every
  new block. Pass `watch: false` on expensive reads.
- `useScaffoldWriteContract` simulates before sending and surfaces the revert
  reason as a toast; it also guards against a wrong-network wallet. Disable with
  `disableSimulate: true`.
- Pass `useScaffoldWriteContract("YourContract")` as a bare string still works
  but is **deprecated** — use the object form above.
- Other hooks in the same barrel: `useScaffoldContract`,
  `useScaffoldEventHistory`, `useScaffoldWatchContractEvent`,
  `useDeployedContractInfo`, `useTransactor`.

Wallet connect is already mounted in the header (RainbowKit), and a burner
wallet is enabled on local networks so you can click through write flows without
touching MetaMask.

There's also a prebuilt `/debug` page that renders a form for every function on
every deployed contract — useful for sanity-checking a write before you build UI
for it.

## Before you ship to users

Two placeholder API keys ship in `scaffold.config.ts` and are shared by every
Scaffold-ETH project in the world — replace them or you'll get rate-limited:

```bash
# packages/nextjs/.env.local
NEXT_PUBLIC_ALCHEMY_API_KEY=...            # dashboard.alchemyapi.io
NEXT_PUBLIC_WALLET_CONNECT_PROJECT_ID=...  # cloud.walletconnect.com
```

Then point `targetNetworks` in `packages/nextjs/scaffold.config.ts` at your real
chain (it defaults to `chains.hardhat`), redeploy with
`yarn deploy --network <name>`, and `yarn vercel` to ship.

Also delete the `import "hardhat/console.sol";` line from `YourContract.sol`
before a live deploy.

## Package names to avoid

Only `create-eth` is maintained. Two similarly named packages still resolve on
npm but are abandoned and will hand you a years-old stack:

- `create-eth-app` — last published 2024-01-10
- `create-scaffold-eth` — last published 2023-01-16

(`create-eth@2.0.23`, last published 2026-07-30, is the live one.)
