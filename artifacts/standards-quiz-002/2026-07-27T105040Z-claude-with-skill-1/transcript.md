Does it revert to a plain EOA after one batch?\n\n**No. The delegation persists indefinitely.** This is the single most commonly\nmis-stated fact about EIP-7702 — there is no auto-expiry, no\none-transaction-only rule, no revert-after-use. The delegation designator is\nwritten into account state and stays there across arbitrary many transactions,\nblocks, and years, exactly like any other account state.\n\nThe standards skill flags this explicitly: *\"Delegation is not automatically\n'single transaction only' by spec. Pointing at the zero address **clears** the designator — the code field is emptied and the account is a bare EOA again |\n\nConstraints on that authorization:\n\n- The `nonce` in the tuple must equal the account's current nonce at processing\n  time. (If the EOA is *also* the sender of the type-4 tx, the tx's own nonce\n  bump happens first, so the authorization nonce must be `account_nonce + 1`.)\n- `chain_id` must match the current chain, **or be `0`**, which makes the\n  authorization replayable on every EIP-7702 chain — convenient for multichain\n  rollout, dangerous if the delegate isn't deployed at the same address\n  everywhere. Prefer an explicit `chain_id` unless you mean it.\n- Anyone can *submit* the transaction and pay the gas; only the EOA's key can\n  *sign* the authorization. Delegation can never be imposed on a user or removed\n  by a third party.\n\n**Two operational consequences worth telling the team about:**\n\n- **Storage is not cleared on re-delegation.** Switching delegates leaves the old\n  delegate's storage layout in the EOA's slots. Migrating between vendors\n  requires layout-compatible implementations (ERC-7201 namespaced storage) or an\n  explicit migration step, or you get slot collisions.\n- **The account now returns non-empty `EXTCODESIZE`.** Anything using\n  `isContract()`, `code.length == 0`, or `tx.origin == msg.sender` as an\n  EOA-check will classify these users as contracts. Worth auditing against the\n  DEX router and any partner integrations before rollout.\n\n---\n\n## 4.
