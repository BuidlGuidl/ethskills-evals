Does it revert to a plain EOA after one transaction?\n\n**No. The delegation is persistent.** It is written into the account's code field in state and\nstays there indefinitely, across any number of subsequent transactions, until it is explicitly\nchanged. There is no expiry, no per-transaction scope, no automatic teardown. (An earlier draft of\n7702 had a one-shot/\"ephemeral\" variant; the version that actually shipped in Pectra does not.\nAnything describing 7702 as per-transaction is describing the abandoned draft.)\n\nTo change or remove it, exactly one thing is required: **a new EIP-7702 authorization signed by\nthat same EOA's private key, included in a type-`0x04` transaction.**\n\n- **To re-point** (upgrade the wallet implementation, switch vendors): sign a new authorization with\n  `address` = the new implementation. It overwrites the previous indicator.\n- **To remove entirely** (back to a plain EOA): sign an authorization with\n  `address = 0x0000000000000000000000000000000000000000`. The spec resets the account's code hash\n  to the empty code hash\n  `0xc5d2460186f7233c927e7db2dcc703c0e500b653ca82273b7bfad8045d85a470`.\n\nEach such authorization consumes a nonce, so old authorization signatures cannot be replayed once\nthe nonce has moved past them.\n\nTwo consequences worth designing around:\n\n- **The root key remains fully sovereign.** The private key can always re-delegate or un-delegate,\n  regardless of what the current implementation says.
