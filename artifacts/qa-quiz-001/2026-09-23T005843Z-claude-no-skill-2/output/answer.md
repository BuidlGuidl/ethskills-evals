# Why `usdcBalance` was `undefined`, why the teammate's fix evaporated, and where USDC actually belongs

## TL;DR

USDC on Base is an **external** contract — you didn't deploy it, so it has no
Hardhat deployment artifact. It must be registered in
`packages/nextjs/contracts/externalContracts.ts`, keyed by chain id `8453`.

`deployedContracts.ts` is a **generated file**: the Hardhat deploy pipeline
rewrites it from scratch on every `yarn deploy`, from whatever is in
`packages/hardhat/deployments/`. A hand-pasted entry there survives exactly
until the next deploy, which is precisely what you observed.

---

## 1. Why the hook returned `undefined` silently instead of throwing

`useScaffoldReadContract` is a thin wrapper around wagmi's `useReadContract`.
Its first move is a *name lookup*, not a network call:

```ts
// packages/nextjs/hooks/scaffold-eth/useScaffoldReadContract.ts (shape)
const { data: deployedContract } = useDeployedContractInfo({ contractName });

return useReadContract({
  chainId: targetNetwork.id,
  address: deployedContract?.address,   // <- undefined when lookup misses
  abi: deployedContract?.abi,           // <- undefined when lookup misses
  functionName,
  args,
  query: { enabled: !Array.isArray(args) || !args.some(a => a === undefined), ... },
});
```

`useDeployedContractInfo` looks the name up in the merged contract registry
(`deployedContracts` deep-merged with `externalContracts`, filtered to the
current `targetNetwork` chain id). `"USDC"` wasn't in either map for chain
`8453`, so `deployedContract` came back `undefined`, and both `address` and
`abi` were passed to wagmi as `undefined`.

That's the whole silence. wagmi v2's `useReadContract` gates its TanStack Query
on the required parameters being present — roughly
`enabled: Boolean(address && abi && functionName && (query.enabled ?? true))`.
With no address and no ABI, the query is **disabled**, not failed:

- the queryFn never runs, so no RPC request is made → **nothing in the network tab**
  (and no *failed* request either, because there was no request);
- a disabled query sits in `status: 'pending'` with `data: undefined` and
  `error: null` → **no runtime error, no error boundary, no console stack**;
- your JSX rendered `undefined`, which React renders as **nothing at all**.

Two secondary reasons nobody got a nudge:

- **The read hook is quiet by design; the write hook isn't.**
  `useScaffoldWriteContract` explicitly detects the missing-contract case and
  fires a user-visible error notification ("Target contract is not deployed, did
  you forget to run `yarn deploy`?"). The read path has no equivalent — a missing
  name is indistinguishable, at runtime, from "not fetched yet."
- **The type error that should have caught it was invisible in dev.**
  `contractName` is typed as a union derived from the generated contract files,
  so `"USDC"` was a genuine TS error (`ContractName` doesn't include it). But
  `next dev` compiles per-route with SWC and does not block on type errors, so
  it only shows up in `yarn next:check-types` / `yarn build`. Worth wiring that
  into CI — it turns this exact class of bug from "blank page, no clue" into a
  build failure.

The general rule: in Scaffold-ETH, a **blank value with no error and no network
request** almost always means *name resolution failed*, not *the call failed*.

## 2. Why the teammate's fix self-destructed on `yarn deploy`

`packages/nextjs/contracts/deployedContracts.ts` is machine-generated. It
carries this header:

```ts
/**
 * This file is autogenerated by Scaffold-ETH.
 * You should not edit it manually or your changes might be overwritten.
 */
```

The generator is the last deploy script in the Hardhat package —
`packages/hardhat/deploy/99_generateTsAbis.ts` — which runs automatically as
part of `yarn deploy`. It walks `packages/hardhat/deployments/<network>/*.json`
(the artifacts hardhat-deploy writes for contracts *it* deployed), builds the
`{ [chainId]: { [contractName]: { address, abi, inheritedFunctions } } }` object,
and **writes the file wholesale with `fs.writeFileSync`**. It does not merge,
diff, or preserve anything that's already in there.

So the arc is:

1. Teammate pastes a `USDC` entry into `deployedContracts.ts`. The name now
   resolves, the hook gets an address + ABI, the balance renders. Works all week
   because nobody deploys all week.
2. Team ships a contract change with `yarn deploy`. `99_generateTsAbis.ts` runs,
   regenerates the file from the deployments directory.
3. There is no `deployments/base/USDC.json` — you never deployed USDC, Circle
   did — so the `USDC` key simply isn't in the regenerated output. The entry is
   gone, name resolution misses again, page goes blank. Same silent failure,
   now with a plausible-looking culprit ("the deploy broke it") pointing at the
   wrong thing.

That's why Scaffold-ETH ships a *second*, hand-maintained file for contracts it
doesn't deploy.

## 3. The correct registration

**File:** `packages/nextjs/contracts/externalContracts.ts`

This file is never generated or touched by the deploy pipeline. It's deep-merged
with `deployedContracts` by `utils/scaffold-eth/contract.ts`, so
`useScaffoldReadContract({ contractName: "USDC", ... })` at your call site needs
**no change** — the name resolves through exactly the same path, and `"USDC"`
becomes a valid member of the `ContractName` union, fixing the type error too.

```ts
import { GenericContractsDeclaration } from "~~/utils/scaffold-eth/contract";

/**
 * @example
 * const externalContracts = {
 *   1: {
 *     DAI: { address: "0x...", abi: [...] },
 *   },
 * } as const;
 */
const externalContracts = {

          inputs: [{ name: "account", type: "address" }],
          outputs: [{ name: "", type: "uint256" }],
        },
        {
          type: "function",
          name: "decimals",
          stateMutability: "view",
          inputs: [],
          outputs: [{ name: "", type: "uint8" }],
        },
        {
          type: "function",
          name: "symbol",
          stateMutability: "view",
          inputs: [],
          outputs: [{ name: "", type: "string" }],
        },
        {

            { name: "owner", type: "address" },
            { name: "spender", type: "address" },

```

Addresses, for reference:

| Network | Chain id | USDC (native Circle USDC) |
| --- | --- | --- |
| Base mainnet | `8453` | `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` |
| Base Sepolia | `84532` | `0x036CbD53842c5426634e7929541eC2318f3dCF7e` |

If the app runs against both, add both chain-id keys — the registry is looked up
per `targetNetwork`, so a Base-Sepolia session with only an `8453` entry
reproduces the identical silent-`undefined` bug.

### Three details that bite here

1. **`as const` is load-bearing.** The ABI must be a const-asserted literal for
   wagmi/viem/abitype to infer `balanceOf`'s argument and return types. Without
   it you get `unknown`/`any` and lose the type safety that would have caught
   the original mistake.
2. **USDC on Base is a proxy.** `0x8335...2913` is an upgradeable proxy in front
   of Circle's `FiatTokenV2_2` implementation. Register the **implementation**
   ABI (or a hand-written ERC-20 subset as above), *not* the proxy's ABI — the
   proxy ABI has no `balanceOf`, so you'd trade a missing-contract miss for a
   "function does not exist on ABI" viem error. You only need the functions you
   actually call; the subset above is fine and keeps the bundle small.
3. **`decimals` is 6, not 18.** Format with
   `formatUnits(usdcBalance ?? 0n, 6)`, and remember the value is `undefined`
   on the first render — keep a loading/zero fallback rather than rendering the
   raw value.

### Guardrails so this doesn't recur

- Add `yarn next:check-types` to CI. The `ContractName` union makes every
  unregistered contract a compile error; you just need something that reads it.
- Treat the "autogenerated — do not edit" header as binding. Anything hand-added
  to `deployedContracts.ts` has a lifetime of exactly one `yarn deploy`.
- Rule of thumb: **did our Hardhat project deploy it?** Yes →
  `deployedContracts.ts` (automatic, never hand-edited). No, it's someone
  else's live contract (USDC, WETH, Uniswap, Aave, an NFT collection) →
  `externalContracts.ts` (manual, permanent).
