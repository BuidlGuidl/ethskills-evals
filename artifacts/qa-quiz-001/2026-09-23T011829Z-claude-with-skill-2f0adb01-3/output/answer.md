# Why `usdcBalance` was `undefined`, why the "fix" vanished, and how to register USDC properly

## 1. Why the hook returned `undefined` silently

`useScaffoldReadContract` is not a thin wrapper around wagmi's `useReadContract`. It first
resolves the contract by *name* against Scaffold-ETH's contract registry:

```ts
const { data: deployedContract } = useDeployedContractInfo({ contractName });
// ...
return useReadContract({
  chainId: targetNetwork.id,
  address: deployedContract?.address,
  abi: deployedContract?.abi,
  functionName,
  args,
  query: {
    ...
    enabled: !!deployedContract && (!Array.isArray(args) || !args.some(arg => arg === undefined)),
  },
});
```

The registry (`packages/nextjs/contracts/index.ts`) is the merge of `deployedContracts.ts` and
`externalContracts.ts`, keyed by **chain id → contract name**. USDC was in neither, for chain
`8453`. So:

- `useDeployedContractInfo` resolved to `undefined` — a miss is a normal, expected state
  (a contract may simply not be deployed on the current network), so it returns nothing rather
  than throwing.
- `address` and `abi` came back `undefined`, and the `enabled` guard evaluated to `false`.
- A disabled TanStack Query never fires. That is why the **network tab showed no failed
  request** — there was no request at all, not a request that 404'd.
- A disabled query's `data` is `undefined` and its `error` is `null`. Nothing to render, nothing
  to throw. `usdcBalance` stayed `undefined` forever, and the component rendered empty.

This is the trap: the failure mode is *absence*, not error. The same `enabled` guard also swallows
the case where `connectedAddress` is `undefined` (wallet not connected) — one more reason an empty
balance here looks identical to a wiring bug, and why you should not read "no error" as "the lookup
worked."

Worth noting for the write side: `useScaffoldWriteContract` *does* complain loudly
(`notification.error("Target Contract is not deployed, did you forget to run 'yarn deploy'?")`).
Reads are quiet. So the symptom only appears on read paths.

## 2. Why the teammate's fix self-destructed on `yarn deploy`

`packages/nextjs/contracts/deployedContracts.ts` is **generated output, not source**. The header
says so:

```ts
/**
 * This file is autogenerated by Scaffold-ETH.
 * You should not edit it manually or your changes might be overwritten.
 */
```

In the hardhat flavor, `yarn deploy` runs `hardhat deploy`, and
`packages/hardhat/scripts/generateTsAbis.ts` runs as a post-deploy step (wired through
`hardhat-deploy`'s run-on-finish hook / the `deploy` package script). It walks
`packages/hardhat/deployments/<network>/*.json`, builds the full contracts object from those
artifacts, and **overwrites `deployedContracts.ts` wholesale** — it does not merge with the file's
previous contents.

USDC on Base has no deployment artifact in `packages/hardhat/deployments/` — nobody deployed it,
Circle did, years ago. So the regenerated file contained only the team's own contracts, and the
hand-pasted USDC entry was erased. It "worked all week" purely because nobody ran a deploy that
week; the next `yarn deploy` reset the file to its generated truth and the payouts page went blank
again. Same thing would happen to any teammate who cloned fresh and deployed, and the entry would
also reappear as noise in every diff.

## 3. The correct registration

Third-party / pre-existing contracts go in **`packages/nextjs/contracts/externalContracts.ts`**.
That file is hand-maintained, never touched by codegen, and is merged into the same registry
`useScaffoldReadContract` reads from — so the hook resolves `contractName: "USDC"` with no call-site
changes.

Base mainnet is chain id **8453**. Native USDC on Base is
**`0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`** (6 decimals). Do not confuse it with bridged
USDbC, `0xd9aAEc86B65D86f6A7B5B1b0c42FFA531710b6CA` — different token, different balance.

```ts
import { erc20Abi } from "viem";
import { GenericContractsDeclaration } from "~~/utils/scaffold-eth/contract";

const externalContracts = {
  8453: {
    USDC: {
      address: "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      abi: erc20Abi,
    },
  },
} as const satisfies GenericContractsDeclaration;

export default externalContracts;
```

`viem`'s `erc20Abi` covers `balanceOf`, `decimals`, `symbol`, `transfer`, `approve`, `allowance`
and the standard events — enough for a payouts page, and it keeps the file readable. If you need
USDC-specific surface (e.g. `permit` / EIP-2612 for gasless approvals, or `version`), paste the
proxy's full ABI inline as an `as const` array instead — and take it from the **implementation**
contract, since USDC on Base is behind a proxy and the proxy's own ABI won't include the token
methods.

### Points worth checking after the change

- **`targetNetworks` must include Base.** `useScaffoldReadContract` uses
  `targetNetwork.id` to pick the chain id, so if `scaffoldConfig.targetNetworks` is still
  `[chains.hardhat]` the lookup goes to chain `31337`, misses again, and you are back to a silent
  `undefined`. Add `chains.base` in `packages/nextjs/scaffold.config.ts`.
- **Add the entry per chain you support.** `externalContracts` is keyed by chain id; a Base Sepolia
  build needs its own `84532` block with the testnet USDC address
  (`0x036CbD53842c5426634e7929541eC2318f3dCF7e`).
- **Format with 6 decimals**, not 18 — `formatUnits(usdcBalance ?? 0n, 6)`. Reusing an ETH-shaped
  formatter here silently renders a balance a trillion times too small.
- **Keep distinguishing the states.** `usdcBalance === undefined` still means "not fetched yet or
  query disabled." Render a loading state off `isLoading` and gate on `connectedAddress` explicitly
  rather than letting all three empty states collapse into one blank span.
- **Name collisions:** if a contract of the same name exists in `deployedContracts` for the same
  chain, the merge resolves to one of them — avoid reusing a name your deploy scripts emit.
