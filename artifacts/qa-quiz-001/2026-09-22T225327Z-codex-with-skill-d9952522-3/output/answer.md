`useScaffoldReadContract` only works for contracts that Scaffold-ETH knows about by
name on the current chain. It resolves `contractName: "USDC"` through the
registered contract metadata first. When `USDC` was not registered for Base,
there was no address/ABI pair for the hook to pass into the underlying wagmi read.
So the query never became a real onchain call: `data` stayed `undefined`, there was
no reverted contract call, and the browser network tab had no failed RPC request
to show.

The teammate's fix worked because adding `USDC` to
`packages/nextjs/contracts/deployedContracts.ts` gave the scaffold hook the
metadata it was missing. But that file is generated by the hardhat deploy flow.
When the team later ran `yarn deploy`, Scaffold regenerated
`deployedContracts.ts` from the app's own deployed contracts, and the hand-added
external token entry was overwritten.

External contracts belong in:

```text
packages/nextjs/contracts/externalContracts.ts
```

For Base USDC, register it there under chain id `8453`:

```typescript
import { GenericContractsDeclaration } from "~~/utils/scaffold-eth/contract";

const externalContracts = {
  8453: {
    USDC: {
      address: "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      abi: [
        {
          inputs: [{ internalType: "address", name: "account", type: "address" }],
          name: "balanceOf",
          outputs: [{ internalType: "uint256", name: "", type: "uint256" }],
          stateMutability: "view",
          type: "function",
        },
      ],
    },
  },
} as const;

export default externalContracts satisfies GenericContractsDeclaration;
```

With that durable registration in place, the existing `/payouts` hook can resolve
`USDC` on Base, build the read with the Base USDC address and ABI, and survive
future `yarn deploy` runs.
