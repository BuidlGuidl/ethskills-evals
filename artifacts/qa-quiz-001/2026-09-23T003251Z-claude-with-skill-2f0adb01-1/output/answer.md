# Why `useScaffoldReadContract({ contractName: "USDC" })` silently returned `undefined`

## Short version

`useScaffoldReadContract` doesn't know any addresses. It looks the contract up **by name** in
Scaffold-ETH's contract registry, and there is no entry named `USDC` there. USDC on Base is not a
contract you deployed, so it never lands in `deployedContracts.ts` — it belongs in
`externalContracts.ts`, which is the hand-maintained file that `yarn deploy` does not touch.

---

## 1. Why it failed silently instead of throwing

The hook is a thin wrapper around wagmi's `useReadContract`. Roughly what it does:

```ts
const { data: deployedContract } = useDeployedContractInfo({ contractName });

return useReadContract({
  chainId: targetNetwork.id,
  address: deployedContract?.address,   // <- undefined
  abi:     deployedContract?.abi,       // <- undefined
  functionName,
  args,
  query: { enabled: ... },
});
```

`useDeployedContractInfo` resolves the name against the merged contract map
(`deployedContracts.ts` deep-merged with `externalContracts.ts`), scoped to the **currently
selected target network's chain id**. A miss is not an exception — it just returns `undefined`.

So `address` and `abi` arrive at wagmi as `undefined`. wagmi treats a query with no `address`/`abi`
as **not ready** and leaves it disabled: the query never enters `fetching`, no RPC call is made, no
error object is produced. `data` sits at `undefined` forever, `isError` is `false`, `isLoading` is
`false`. That is exactly the three symptoms reported: blank render, no thrown error, no network
request. A disabled query is indistinguishable at the call site from "loading nothing".

The one place this *did* surface is TypeScript. `contractName` is typed against a `ContractName`
union generated from the contract files, so `"USDC"` is not assignable and `tsc` would flag it. But
the Next.js dev server compiles with SWC and does not block on type errors — the type error only
appears in the editor / terminal / `yarn next:check-types`, never in the browser. Type-checking
happens at `yarn build`. That is the gap the bug lived in all week.

**Debug heuristic:** when a `useScaffold*` hook returns `undefined` with no error and no network
activity, the contract lookup missed. Check `useDeployedContractInfo` directly, and check the chain
id — a contract registered only under `31337` is invisible while the app targets `8453`.

## 2. Why the teammate's fix self-destructed

`packages/nextjs/contracts/deployedContracts.ts` is a **generated artifact, not source**. Its own
header says as much:

```
// This file is autogenerated by Scaffold-ETH.
// You should not edit it manually or your changes might be overwritten.
```

`yarn deploy` runs `hardhat deploy`, and Scaffold-ETH's `generateTsAbis` step then walks
`packages/hardhat/deployments/<network>/*.json` and **rewrites the whole file from scratch** out of
those artifacts. It is a full overwrite, not a merge.

USDC on Base has no deployment artifact in your repo — you never deployed it — so the
hand-pasted entry had nothing backing it and was simply not re-emitted. The next `yarn deploy`
erased it, the lookup missed again, and the page went blank. It "worked all week" only because
nobody ran a deploy in between. The same would have happened on any teammate's fresh clone, in CI,
or on any `yarn deploy --network base`.

This is the general rule: **anything in `deployedContracts.ts` must be reproducible from a Hardhat
deployment.** Editing it is always temporary.

## 3. The correct registration

Third-party / pre-existing contracts go in **`packages/nextjs/contracts/externalContracts.ts`**.
That file is plain source, checked in, never regenerated, and Scaffold-ETH deep-merges it with
`deployedContracts.ts` before the name lookup — so `useScaffoldReadContract`,
`useScaffoldWriteContract`, `useScaffoldEventHistory` and the Debug Contracts page all work against
it identically, and `"USDC"` becomes a valid member of the `ContractName` union so autocomplete and
`args` typing come back.

It is keyed by **chain id** at the top level. Base mainnet is `8453`.

```ts
import { GenericContractsDeclaration } from "~~/utils/scaffold-eth/contract";

const externalContracts = {
  8453: {
    USDC: {
      address: "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      abi: [
        {
          type: "function",
          name: "balanceOf",
          stateMutability: "view",
          inputs: [{ name: "account", type: "address" }],
          outputs: [{ name: "", type: "uint256" }],
        },
        {
          type: "function",
          name: "decimals",
          stateMutability: "view",
          inputs: [],
          outputs: [{ name: "", type: "uint8" }],
        },
        {
          type: "function",
          name: "symbol",
          stateMutability: "view",
          inputs: [],
          outputs: [{ name: "", type: "string" }],
        },
        {
          type: "function",
          name: "allowance",
          stateMutability: "view",
          inputs: [
            { name: "owner", type: "address" },
            { name: "spender", type: "address" },
          ],
          outputs: [{ name: "", type: "uint256" }],
        },
        {
          type: "function",
          name: "approve",
          stateMutability: "nonpayable",
          inputs: [
            { name: "spender", type: "address" },
            { name: "amount", type: "uint256" },
          ],
          outputs: [{ name: "", type: "bool" }],
        },
        {
          type: "function",
          name: "transfer",
          stateMutability: "nonpayable",
          inputs: [
            { name: "to", type: "address" },
            { name: "amount", type: "uint256" },
          ],
          outputs: [{ name: "", type: "bool" }],
        },
        {
          type: "event",
          name: "Transfer",
          inputs: [
            { name: "from", type: "address", indexed: true },
            { name: "to", type: "address", indexed: true },
            { name: "value", type: "uint256", indexed: false },
          ],
          anonymous: false,
        },
      ],
    },
  },
} as const satisfies GenericContractsDeclaration;

export default externalContracts;
```

### Details that matter

- **Address.** `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913` is native Circle USDC on Base mainnet.
  Don't confuse it with USDbC (bridged, `0xd9aAEc86B65D86f6A7B5B1b0c42FFA531710b6CA`), which is a
  different token and mostly deprecated. For Base Sepolia (chain `84532`) the test USDC is
  `0x036CbD53842c5426634e7929541eC2318f3dCF7e` — add it as a second top-level key if you deploy
  there, since the lookup is per-chain.
- **ABI.** USDC is an upgradeable proxy (`FiatTokenProxy`), so pulling "the ABI" off the block
  explorer for the proxy address gives you the proxy's ABI, not the token's. Hand-writing the ERC-20
  subset you actually call, as above, is the simplest correct answer; if you need the full surface
  (`permit`, `EIP-3009` transfer-with-authorization), take the ABI from the **implementation**
  contract.
- **`as const satisfies GenericContractsDeclaration`** is load-bearing. Without `as const` the ABI
  widens to `object[]`, and you lose the typed `functionName` / `args` / return-value inference that
  makes the scaffold hooks worth using — `usdcBalance` would come back as `unknown` instead of
  `bigint`.
- **`scaffold.config.ts` must target Base.** `targetNetworks: [chains.base]`. The lookup is scoped
  to the selected target network, so a correct `8453` entry is still invisible while the app is
  pointed at `hardhat`/`31337`. This is the most common follow-up failure after fixing the file.
- **Rendering.** USDC has 6 decimals, not 18. Format with
  `formatUnits(usdcBalance ?? 0n, 6)`, not `formatEther`.
- **Still handle `undefined`.** Even once registered, the value is `undefined` on first render and
  whenever `connectedAddress` is undefined (wallet not connected) — the hook disables the query when
  any arg is `undefined`. Render a skeleton or `0` for that state rather than letting it fall through
  to an empty string, which is what made the original bug invisible.

## Summary

| | |
|---|---|
| Symptom | `usdcBalance === undefined`, no error, no request |
| Cause | Name lookup miss → `address`/`abi` undefined → wagmi query never enabled |
| Why silent | A disabled query isn't an error; the only signal was a TS error the dev server doesn't block on |
| Why the patch vanished | `deployedContracts.ts` is regenerated wholesale from Hardhat deployment artifacts on every `yarn deploy` |
| Fix | Add the entry to `packages/nextjs/contracts/externalContracts.ts` under chain `8453`, and target Base in `scaffold.config.ts` |
