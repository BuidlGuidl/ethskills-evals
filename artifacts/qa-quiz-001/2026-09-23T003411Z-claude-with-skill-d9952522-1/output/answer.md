# Why `useScaffoldReadContract("USDC")` returned `undefined`, why the fix vanished, and the right registration

## TL;DR

USDC was never registered with Scaffold-ETH's contract registry, so the hook
disabled its own query instead of calling the chain. The teammate registered it in
the **generated** file, which `yarn deploy` rewrites from scratch. USDC is an
*external* contract and belongs in `packages/nextjs/contracts/externalContracts.ts`.

---

## 1. Why the hook returned `undefined` silently

`useScaffoldReadContract` does not take an address. It takes a **name**, and resolves
that name through `useDeployedContractInfo(contractName)`, which looks the name up in
the merged contract registry (`deployedContracts` + `externalContracts`) for the
currently targeted chain.

When the name isn't in the registry, the lookup doesn't throw — it just comes back
empty. The hook then calls wagmi's `useReadContract` with `address: undefined` and
`abi: undefined`, and gates the query:

```ts
query: {
  enabled: !!deployedContractData && (!Array.isArray(args) || !args.some(arg => arg === undefined)),
  ...
}
```

With `enabled: false`, TanStack Query never runs the queryFn. So:

- **No request** — nothing ever reaches the RPC transport, which is exactly why the
  network tab is clean. There is no failed request because there was no request.
- **No error** — a disabled query has `status: "pending"`, `error: null`,
  `data: undefined`. That's the same shape as "still loading," so a component doing
  `usdcBalance ? format(usdcBalance) : null` renders nothing, forever, and looks like
  a slow load rather than a bug.
- **No `isError`** to branch on either — this is a deliberate design in SE-2: an
  unregistered or not-yet-deployed contract is a normal state (e.g. the chain you
  switched to doesn't have it), not an exception.

There's a second reason it slipped through. `contractName` is typed as a union of the
registered contract names, so `"USDC"` *should* be a TypeScript error. But Next.js dev
mode transpiles without type-checking — the page compiles and runs regardless.
`yarn next:check-types` would have failed on this from the start; the dev server never
will. (A related silent-undefined trap: if `connectedAddress` is `undefined` because
no wallet is connected, the `args.some(arg => arg === undefined)` clause disables the
query too. Worth ruling out, but here the cause was registration.)

## 2. Why the teammate's fix self-destructed

`packages/nextjs/contracts/deployedContracts.ts` is a **build artifact**. It carries a
header to that effect:

```ts
/**
 * This file is autogenerated by Scaffold-ETH.
 * You should not edit it manually or your changes might be overwritten.
 */
```

It is produced by the `generateTsAbis` post-deploy script in `packages/hardhat`, which
runs at the end of every `yarn deploy`. That script reads
`packages/hardhat/deployments/<network>/*.json` and **writes the whole file from
scratch** — it does not merge with, diff against, or preserve the previous contents.

USDC on Base was not deployed by this project, so there is no
`deployments/base/USDC.json`. The next `yarn deploy` regenerated the file from the
deployments directory, the hand-pasted USDC entry wasn't in that source of truth, and
it was overwritten out of existence. The page went back to rendering nothing, for
exactly the same reason as before.

It "worked all week" only because nobody ran a deploy that week. This is a
deploy-triggered time bomb, not an intermittent bug — and it would have re-detonated
on every deploy, plus on any fresh clone that runs `yarn deploy` before `yarn start`.

## 3. The correct registration

Contracts the project **does not deploy** — tokens, protocols, anything already live
on-chain — go in `packages/nextjs/contracts/externalContracts.ts`. That file is
hand-maintained, git-tracked, and never touched by the codegen. SE-2 deep-merges it
with `deployedContracts` before the hooks see it, so `useScaffoldReadContract`,
`useScaffoldWriteContract`, `useScaffoldEventHistory`, and the Debug Contracts page all
resolve `"USDC"` identically to a locally deployed contract.

```typescript
// packages/nextjs/contracts/externalContracts.ts
import { GenericContractsDeclaration } from "~~/utils/scaffold-eth/contract";

/**
 * @example
 * const externalContracts = {
 *   1: {
 *     DAI: { address: "0x...", abi: [...] },
 *   },
 * } as const;
 */
const externalContracts = {
  8453: {
    USDC: {
      // Native (Circle-issued) USDC on Base — 6 decimals
      address: "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      abi: [
        {
          type: "function",
          name: "balanceOf",
          stateMutability: "view",
          inputs: [{ name: "account", type: "address" }],
          outputs: [{ name: "", type: "uint256" }],
        },
        {
          type: "function",
          name: "decimals",
          stateMutability: "view",
          inputs: [],
          outputs: [{ name: "", type: "uint8" }],
        },
        {
          type: "function",
          name: "allowance",
          stateMutability: "view",
          inputs: [
            { name: "owner", type: "address" },
            { name: "spender", type: "address" },
          ],
          outputs: [{ name: "", type: "uint256" }],
        },
        {
          type: "function",
          name: "approve",
          stateMutability: "nonpayable",
          inputs: [
            { name: "spender", type: "address" },
            { name: "amount", type: "uint256" },
          ],
          outputs: [{ name: "", type: "bool" }],
        },
        {
          type: "function",
          name: "transfer",
          stateMutability: "nonpayable",
          inputs: [
            { name: "to", type: "address" },
            { name: "amount", type: "uint256" },
          ],
          outputs: [{ name: "", type: "bool" }],
        },
        {
          type: "event",
          name: "Transfer",
          inputs: [
            { name: "from", type: "address", indexed: true },
            { name: "to", type: "address", indexed: true },
            { name: "value", type: "uint256", indexed: false },
          ],
          anonymous: false,
        },
      ],
    },
  },
} as const;

export default externalContracts satisfies GenericContractsDeclaration;
```

Details that matter:

- **`8453`** is Base mainnet's chain ID, and it must match a chain in
  `targetNetworks` in `packages/nextjs/scaffold.config.ts`. The registry is keyed by
  chain — a USDC entry under the wrong chain ID reproduces the original silent
  `undefined` exactly. If you also run against Base Sepolia, add an `84532` block with
  that network's USDC address; the hook resolves per connected chain.
- **`0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`** is native Circle USDC on Base. Do
  not use the bridged USDbC address (`0xd9aA...`) unless you specifically mean
  USDbC — they are different tokens with different balances.
- **`as const` is not optional.** It's what gives viem the literal ABI types that make
  `functionName: "balanceOf"` autocomplete and type `usdcBalance` as `bigint`. Widen
  the abi to `Abi` and you lose inference and land back in `any`-shaped territory.
- **USDC is 6 decimals, not 18.** Render with `formatUnits(usdcBalance, 6)` (or
  `useScaffoldReadContract` on `decimals`); `formatEther` will show a balance
  a trillion times too small — which is its own flavor of "renders as nothing."
- **A partial ABI is fine.** Only the functions you actually call need to be present.

## 4. Cleanup steps

1. Add the entry above to `packages/nextjs/contracts/externalContracts.ts`.
2. Restore `packages/nextjs/contracts/deployedContracts.ts` to its generated state —
   `git checkout packages/nextjs/contracts/deployedContracts.ts`, or simply re-run
   `yarn deploy`, which already regenerated it.
3. Run `yarn next:check-types`. It passes only once the name resolves, which is the
   real proof the registration took — and it is the check that would have caught this
   on day one. Consider wiring it into CI / a pre-commit hook.
4. Reload `/payouts` with a wallet on Base and confirm a balance renders. Also load it
   **disconnected**: `connectedAddress` is `undefined` there, the query disables
   again, and you get the same blank. That state should render a
   `RainbowKitCustomConnectButton`, not empty space.
5. While you're in the read path, give the hook a real pending state in the UI
   (skeleton or spinner) so "query disabled" and "query in flight" stop looking
   identical to whoever debugs the next one of these.
