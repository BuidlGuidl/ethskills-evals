# Why the USDC balance was blank, why the "fix" self-destructed, and how to register it properly

## TL;DR

USDC is not a contract *you* deploy, so it never belongs in
`packages/nextjs/contracts/deployedContracts.ts` — that file is machine-generated and
overwritten by every `yarn deploy`. Third-party / pre-existing contracts go in
`packages/nextjs/contracts/externalContracts.ts`, keyed by chain id (Base mainnet =
`8453`). Until the contract is registered somewhere in that merged registry,
`useScaffoldReadContract` has no address to call, so it disables the underlying wagmi
query instead of throwing — hence `undefined`, no error, no network request.

---

## 1. Why the hook returned `undefined` silently

`useScaffoldReadContract` is a thin wrapper over wagmi's `useReadContract`. Roughly:

```ts
const { data: deployedContract } = useDeployedContractInfo(contractName);

return useReadContract({
  chainId: targetNetwork.id,
  address: deployedContract?.address,
  abi: deployedContract?.abi,
  functionName,
  args,
  query: {
    enabled: !!deployedContract && !Array.isArray(args) || !args.some(a => a === undefined),
    ...
  },
});
```

Two things matter here:

**a) Name → address/ABI resolution is a lookup in a static object, not a network call.**
`useDeployedContractInfo` reads from `~~/utils/scaffold-eth/contract`, which builds a
single `contracts` map by deep-merging `deployedContracts.ts` and
`externalContracts.ts`, then indexes it by the *target network's chain id*:

```
contracts[targetNetwork.id]?.[contractName]
```

If `USDC` isn't a key under `8453`, the lookup is a plain object miss →
`deployedContractData === undefined`. Nothing throws; an object miss in JS is just
`undefined`.

**b) wagmi's query is then explicitly disabled.** With `address`/`abi` undefined, the
`enabled` guard is false, so TanStack Query never runs the query function. A disabled
query has `data: undefined`, `error: null`, `isLoading: false` — it is indistinguishable
from "not asked yet". No RPC request is ever issued, which is exactly why the network
tab was empty: there was no failed request because there was no request.

So the failure mode is *fail-silent by design*: the hook treats "contract not known yet"
the same way it treats "still loading deployment info," which is the right behavior
during hot-reload/deploy races but is indistinguishable from a config bug.

**c) The one guardrail that should have caught it was bypassed by `next dev`.**
`contractName` is typed as `ContractName` — a union derived from the keys actually present
in the generated registry. Passing `"USDC"` when no such entry exists is a *TypeScript*
error. But `next dev` transpiles with SWC and does not fail on type errors; only
`yarn next:check-types` (and `next build`) surface them. Some versions also log a
`Contract "USDC" not found` style warning from `useDeployedContractInfo`, which is easy to
miss in a noisy dev console. Net effect: the only signal was a blank span.

Related gotcha worth checking: even a correctly-shaped entry filed under the *wrong* chain
id (e.g. `31337` while `scaffold.config.ts` targets `base`) produces the identical silent
`undefined`. The lookup key is `targetNetwork.id` from `scaffold.config.ts`, not the
wallet's connected chain.

## 2. Why the teammate's fix vanished on `yarn deploy`

`packages/nextjs/contracts/deployedContracts.ts` carries this header for a reason:

```ts
/**
 * This file is autogenerated by Scaffold-ETH.
 * You should not edit it manually or your changes might be overwritten.
 */
```

`yarn deploy` runs `hardhat deploy`, and Scaffold-ETH ships a deploy script that runs last
— `packages/hardhat/deploy/99_generateTsAbis.ts` (it calls into
`packages/hardhat/scripts/generateTsAbis.ts`). That script walks
`packages/hardhat/deployments/<network>/*.json`, serializes every deployment it finds, and
**writes the file from scratch** — it is a full overwrite, not a merge. USDC has no
`deployments/base/USDC.json` (you never deployed it), so it simply wasn't in the
regenerated output. The entry didn't get "deleted" by anyone; it was never re-derived.

It "worked all week" because nobody ran a deploy that week. The fix was a time bomb whose
fuse was the next `yarn deploy` — and it will re-detonate for anyone who runs
`yarn deploy` again, on every machine, forever.

(Aside: this also means the same mistake would break a teammate who runs `yarn deploy`
locally against hardhat — the file is regenerated per deploy, not per network merge.)

## 3. The correct registration

File: **`packages/nextjs/contracts/externalContracts.ts`**

This file is hand-maintained, never touched by codegen, and is deep-merged with
`deployedContracts.ts` into the same registry — so `useScaffoldReadContract`,
`useScaffoldWriteContract`, `<Address />`, the Debug Contracts page, etc. all pick it up
identically, and `contractName: "USDC"` becomes a valid member of the `ContractName` union.

Native USDC on Base mainnet (chain id `8453`) is
`0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`. (Do not confuse it with bridged USDbC,
`0xd9aAEc86B65D86f6A7B5B1b0c42FFA531710b6CA` — different token, different balances.)

```ts
import { GenericContractsDeclaration } from "~~/utils/scaffold-eth/contract";

/**
 * @example
 * const externalContracts = {
 *   1: {
 *     DAI: { address: "0x...", abi: [...] },
 *   },
 * } as const;
 */
const externalContracts = {
  8453: {
    USDC: {
      address: "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      abi: [
        {
          type: "function",
          name: "balanceOf",
          stateMutability: "view",
          inputs: [{ name: "account", type: "address" }],
          outputs: [{ name: "", type: "uint256" }],
        },
        {
          type: "function",
          name: "decimals",
          stateMutability: "view",
          inputs: [],
          outputs: [{ name: "", type: "uint8" }],
        },
        {
          type: "function",
          name: "symbol",
          stateMutability: "view",
          inputs: [],
          outputs: [{ name: "", type: "string" }],
        },
        {
          type: "function",
          name: "transfer",
          stateMutability: "nonpayable",
          inputs: [
            { name: "to", type: "address" },
            { name: "amount", type: "uint256" },
          ],
          outputs: [{ name: "", type: "bool" }],
        },
        {
          type: "function",
          name: "approve",
          stateMutability: "nonpayable",
          inputs: [
            { name: "spender", type: "address" },
            { name: "amount", type: "uint256" },
          ],
          outputs: [{ name: "", type: "bool" }],
        },
        {
          type: "function",
          name: "allowance",
          stateMutability: "view",
          inputs: [
            { name: "owner", type: "address" },
            { name: "spender", type: "address" },
          ],
          outputs: [{ name: "", type: "uint256" }],
        },
        {
          type: "event",
          name: "Transfer",
          inputs: [
            { name: "from", type: "address", indexed: true },
            { name: "to", type: "address", indexed: true },
            { name: "value", type: "uint256", indexed: false },
          ],
          anonymous: false,
        },
      ],
    },
  },
} as const;

export default externalContracts satisfies GenericContractsDeclaration;
```

Notes on the shape:

- **`as const` is required.** Without it the ABI widens to `string`/`any[]` and you lose
  the typed `functionName` / `args` / return-type inference that makes the scaffold hooks
  worth using.
- **Chain id key must match `targetNetworks` in `packages/nextjs/scaffold.config.ts`.** If
  you also run against Base Sepolia (`84532`), add a second top-level key with that
  chain's USDC address (`0x036CbD53842c5426634e7929541eC2318f3dCF7e`).
- **A partial ABI is fine** — include only what the dApp calls. If you'd rather not inline
  it, `import { erc20Abi } from "viem"` and use `abi: erc20Abi` (it's already `as const`).
  Note that Base USDC is a proxy; fetching the ABI from Basescan gives you the *proxy*
  ABI, so either use the implementation ABI or a plain ERC-20 ABI as above.
- **Restart `yarn start`** after editing — the contracts map is imported at module load, so
  a running dev server may need a bounce for the new `ContractName` union to take effect.

## 4. How to keep this from silently recurring

- Run `yarn next:check-types` (or a full `yarn build`) in CI. That turns this exact class of
  bug from an invisible blank into a compile error at the `contractName: "USDC"` call site.
- Treat any hand-edit to a file with an "autogenerated" header as a bug; if it's not yours
  to deploy, it goes in `externalContracts.ts`.
- When a scaffold hook returns `undefined` forever with zero network traffic, check
  registration + chain id *first* — a real RPC problem shows up as a failed request or an
  `error` from the hook, not as silence.
