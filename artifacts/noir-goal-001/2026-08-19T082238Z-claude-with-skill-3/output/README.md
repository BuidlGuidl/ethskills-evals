# Anonymous DAO voting

Yes/no governance votes for a DAO whose membership is public, where nobody — including
the DAO — can tell how any individual member voted.

**[NOTES.md](./NOTES.md) is the thing to read**: the full flow for one member voting on
one proposal, naming for every onchain transaction which wallet sends it and what a
chain observer learns.

## Layout

```
circuits/vote/src/main.nr          the ballot circuit (Noir)
contracts/src/
  MemberRegistry.sol               Poseidon incremental Merkle tree of member commitments
  AnonymousBallot.sol              proposals, proof verification, nullifiers, tally
  PoseidonT3Hasher.sol             BN254 Poseidon, vendored from poseidon-solidity
  HonkVerifier.sol                 generated by `bb write_solidity_verifier` -- do not edit
  demo/MembershipNFT.sol           stand-in for the DAO's real membership NFT
contracts/script/Deploy.s.sol      stands everything up and wires it together
contracts/test/                    Poseidon parity + end-to-end with a real proof
client/
  register.js                      one member: secret -> commitment -> onchain (own wallet)
  vote.js                          one member: secret -> proof -> relayed vote tx
  demo.js                          150 members, one proposal, start to tally
  export-fixture.js                regenerates the proof fixture used by the Solidity tests
  src/{poseidon,identity,tree,prove,chain,args}.js
```

## Setup

Toolchain versions are pinned to each other — `@aztec/bb.js` must match the `bb` CLI,
and `@noir-lang/noir_js` must match `nargo`:

```bash
noirup -v 1.0.0-beta.26
bbup   -v 5.1.0            # bare `bbup` resolves through a version map that lags nargo
npm install
```

## Run

```bash
npm run circuit:build      # nargo compile -> bb write_vk (--verifier_target evm) -> HonkVerifier.sol
npm run circuit:test
npm run contracts:test

anvil                      # separate terminal
npm run deploy:local       # writes contracts/deployments/31337.json
node client/demo.js        # 150 members register, 7 vote via a relayer, tally after deadline
```

One member on their own:

```bash
node client/register.js --token 73 --account 173 --note client/notes/member-73.json
node client/vote.js --proposal 0 --support yes --note client/notes/member-73.json
```

`client/notes/*.json` holds members' secrets. It is gitignored; losing a note means
losing the ability to vote, with no recovery.

## Regenerating the verifier

`contracts/src/HonkVerifier.sol` is generated from the circuit. After any change to
`circuits/vote`, re-run both, in this order:

```bash
npm run circuit:build
node client/export-fixture.js     # the Solidity tests verify a real proof; it must match
```

## Notes on the environment

* The generated verifier needs `pragma >=0.8.21`, `evm_version = "cancun"`, and the
  optimizer on to stay under the 24KB code limit. All three are set in `foundry.toml`.
* Proving keys and proofs must agree on serialization: the VK is written with
  `--verifier_target evm` and the client proves with `{ verifierTarget: "evm" }`. The
  default serialization does not verify onchain.
* If node fails with "tried to access X, but it isn't declared in your dependencies",
  a parent directory's Yarn PnP loader is being injected via `NODE_OPTIONS`. Run the
  scripts with `env -u NODE_OPTIONS node ...`.
