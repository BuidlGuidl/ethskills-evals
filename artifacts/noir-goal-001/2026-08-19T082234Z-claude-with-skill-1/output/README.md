# dao-anon-vote

Contested yes/no governance votes for a DAO whose membership is public, where
nobody — including the DAO — can tell how any individual member voted.

**[NOTES.md](./NOTES.md) is the document to read**: the end‑to‑end flow, who
sends each transaction, what a chain observer learns from it, and the three
residual leaks that are not solved by cryptography.

## Quickstart

```bash
npm install
npm run build     # nargo test && nargo compile, then forge build
npm test          # 13 Solidity tests, including a real proof through the real verifier

anvil             # terminal 1
npm run deploy    # terminal 2 — deploys and wires everything on the local chain
npm run demo      # 12 members join, a proposal opens, 6 anonymous ballots, the tally
```

Toolchain this was built and tested against: `nargo 1.0.0-beta.26`,
`bb 5.1.0`, `forge 1.4.4`, Node 22. Install Noir with `noirup -v <version>` then
`bbup -v <version>` — bare `bbup` resolves through a version map that lags nargo.

## Layout

```
circuits/vote/src/main.nr        the proof: membership + proposal-scoped nullifier + boolean vote
contracts/src/
  MemberRegistry.sol             incremental Poseidon Merkle tree of identity commitments
  AnonymousBallot.sol            proposals, verification, nullifiers, tally
  MembershipNFT.sol              stand-in for the DAO's existing NFT
  verifier/HonkVerifier.sol      generated by `bb write_solidity_verifier` — never edit
contracts/script/Deploy.s.sol    stands the system up on a local chain and wires it
contracts/test/                  Solidity tests, incl. a baked real proof fixture
scripts/
  join.mjs propose.mjs vote.mjs tally.mjs      the four member-facing commands
  demo.mjs                                     all of the above, in order
  check-hash-parity.mjs                        circuit / contract / client Poseidon must agree
  gen-fixture.mjs                              rebake the proof used by the Solidity tests
  client/                                      identity, offchain tree mirror, in-process prover
```

`out/`, `cache/`, `broadcast/`, `node_modules/` and `circuits/vote/target/` are
generated and gitignored. So is `notes/` — those files are member secrets and
anyone holding one can vote as that member.

`lib/` is *not* ignored: forge-std and poseidon-solidity are git submodules, so
their revisions are pinned. Restore with
`git submodule update --init --recursive`.

## Regenerating after a circuit change

The Solidity verifier is generated from the circuit's verification key, and the
Solidity tests run a proof baked from the compiled circuit. Change the circuit
and all three must be redone, or `forge test` fails:

```bash
npm run circuit    # nargo test && nargo compile
npm run verifier   # bb write_vk --verifier_target evm  →  bb write_solidity_verifier
npm run fixture    # node scripts/gen-fixture.mjs
```
