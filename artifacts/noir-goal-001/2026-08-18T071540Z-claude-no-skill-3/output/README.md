# DAO private ballot

Contested yes/no governance votes for a ~150-member DAO, with a public tally and
**no vote attribution** — including by the DAO operators.

Membership stays public. What this breaks is the link between a member and their
vote, using a Noir membership proof plus a nullifier, submitted by a wallet that
is not the member's.

**Read [NOTES.md](NOTES.md)** for the end-to-end flow, who sends which
transaction, what an observer learns from each one, and the residual leaks.

## Layout

```
circuits/vote/src/main.nr        the ZK circuit (membership + nullifier + vote)
contracts/src/
  Hashes.sol                     the one hash definition, mirrored in Noir and JS
  MemberRegistry.sol             NFT-gated append-only Merkle tree of commitments
  PrivateBallot.sol              proposals, proof checking, nullifiers, tally
  MembershipNFT.sol              local stand-in for the DAO's real NFT
  verifier/HonkVerifier.sol      generated by `bb write_solidity_verifier`
contracts/script/Deploy.s.sol    stands everything up and wires it together
contracts/test/                  24 tests, incl. a real proof verified on-chain
scripts/vote.mjs                 one member: secret -> proof -> submitted vote
scripts/common/crypto.mjs           commitments, nullifiers, Merkle tree (JS side)
scripts/e2e.sh                   whole flow on a throwaway anvil
```

## Quick start

```bash
npm run setup     # npm install + forge install
npm run test      # contracts + a real UltraHonk proof
./scripts/e2e.sh  # deploy, register 150 members, propose, vote, tally
```

Requires `nargo` (1.0.0-beta.26), `bb` (5.1.0), `forge`, and Node 18+.

## The one thing not to get wrong

The circuit hides *which member* voted. It does not hide the yes/no bit of an
individual vote — that has to be readable for the tally to be public and
trustless. So anonymity rests on the vote transaction being sent and paid for by
a wallet with no link to the member. `scripts/vote.mjs` shows that path; NOTES.md
§5 covers how to avoid re-linking it.
