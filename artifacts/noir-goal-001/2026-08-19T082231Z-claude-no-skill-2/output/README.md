# DAO private ballot

Anonymous yes/no governance voting for a DAO whose membership is public. Members
publish a commitment once, then prove membership in zero knowledge each time they
vote. Ballots are unlinkable to members — including by the DAO.

**[NOTES.md](NOTES.md) is the document to read**: the end-to-end flow for one member
voting on one proposal, who sends each transaction, what it reveals, and what still
leaks.

## Layout

```
circuits/vote/          Noir circuit (nargo)
src/                    Solidity contracts (foundry)
  MemberRegistry.sol      onchain incremental Merkle tree over member commitments
  PrivateBallot.sol       proposals, nullifier spend set, tally
  FieldHash.sol           the one hash shared by circuit / EVM / Node
  demo/MembershipNFT.sol  stand-in for your real membership NFT
  verifiers/              generated Honk verifier - do not hand-edit
script/Deploy.s.sol     deploys and wires everything
test/                   forge tests, including real proofs verified onchain
js/                     member tooling: register, propose, vote, tally
scripts/                build the circuit, deploy to a local chain
```

## Requirements

`nargo` 1.0.0-beta.26, `bb` 5.1.0, `foundry`, Node 20+.

## Quick start

```bash
npm install
bash scripts/build-circuit.sh     # nargo test + compile, regenerate the verifier
forge test                        # 24 tests, incl. real proofs verified onchain
bash scripts/deploy-local.sh      # starts anvil if needed, writes deployments/local.json
node js/demo.js                   # register 8 members, propose, 3 ballots, tally
```

## One member's path

```bash
MEMBER=0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d  # anvil #1
RELAYER=0x2a871d0798f97d79848a013d4936a73bf4cc922c825d33c1cf7073dff6d409c6 # anvil #9, no NFT

node js/register.js --key $MEMBER --passphrase "correct horse battery staple"
node js/propose.js  --key $MEMBER --text "Fund the audit from the treasury?" --hours 72
node js/vote.js --proposal 0 --support yes \
                --passphrase "correct horse battery staple" \
                --relayer-key $RELAYER
node js/tally.js --proposal 0
```

`js/vote.js --print-calldata` stops before sending and prints a transaction for
someone else to broadcast. That is the production shape: the member proves locally, a
relayer pays and sends, and the relayer learns nothing it could not read off the chain
afterwards. The proof names the submitter, so nobody else can broadcast it and the
relayer cannot alter the vote.

## Regenerating the circuit

Any change under `circuits/vote/src` changes the verification key, which means the
verifier contract and the committed proof fixtures must both be regenerated:

```bash
bash scripts/build-circuit.sh
node js/gen-fixture.js            # rewrites test/fixtures/ballot.json
forge test
```

## Notes

- `src/verifiers/HonkVerifier.sol` is generated by `bb` and committed so that
  `forge build` works from a bare clone. Regenerate it, never edit it.
- The Foundry project has no external Solidity dependencies — no `forge install`, no
  submodules. The handful of cheatcodes the tests and deploy script use are declared
  in `script/Cheats.sol`.
- If Node fails with a Yarn PnP resolution error, an inherited `NODE_OPTIONS` from a
  parent workspace is interfering; run with `NODE_OPTIONS= node js/...`.
