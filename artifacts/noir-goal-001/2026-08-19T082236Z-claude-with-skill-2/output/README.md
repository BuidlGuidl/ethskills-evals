# Anonymous DAO voting

Yes/no governance votes for a public, NFT-gated membership, where the tally is public and
nobody — including the DAO — can tell how any individual member voted.

**Read [NOTES.md](./NOTES.md) first.** It walks one member through one proposal and names,
for every onchain transaction, which wallet sends it and what a chain observer learns.

## Toolchain

Pinned; `bb.js` must match the `bb` CLI exactly or proofs will not verify.

| Tool | Version |

```bash
noirup -v 1.0.0-beta.26

```

## Build

```bash
npm install
forge install                 # forge-std, poseidon-solidity
npm run circuit:build         # nargo compile -> bb write_vk -> HonkVerifier.sol
forge build
forge test                    # 19 tests, incl. a real proof against the real verifier
```

`npm run circuit:build` regenerates `contracts/verifier/HonkVerifier.sol`. It is committed so
`forge build` works from a clean checkout without the Noir toolchain, but it is generated —
never hand-edit it.

## Run it on a local chain

```bash
anvil                                                     # terminal 1

export RPC_URL=http://127.0.0.1:8545                      # terminal 2
forge script script/Deploy.s.sol --broadcast --rpc-url $RPC_URL
npm run demo
```

`npm run demo` seeds a 150-member electorate, opens a proposal, casts 12 relayed ballots,
shows the double-vote attempt being rejected, warps past the deadline and reads the tally.
Takes about 30 seconds.

The individual steps, if you want to drive them by hand:

```bash
MEMBER_INDEX=7 node js/join.mjs                           # member's own wallet
PROPOSER_INDEX=0 TEXT="Ship v2" node js/propose.mjs       # a member's own wallet
MEMBER_INDEX=7 PROPOSAL_ID=1 VOTE=yes node js/vote.mjs    # proof local, tx via the relayer
PROPOSAL_ID=1 node js/tally.mjs                           # view call, after the deadline
```

`script/Deploy.s.sol` deploys and wires everything and mints the membership badges. It does
**not** insert any voter commitments — only a member can do that, from their own wallet,
because only they know their secret. `js/seed.mjs` does that for all 150 on a local chain.

Members are HD indices `0..149` of anvil's default mnemonic; the relayer is index `900`,
deliberately outside the member range. Override with `MNEMONIC`, `MEMBER_COUNT`, `RPC_URL`.

## Layout

Everything below is hand-written source except where noted.

```
circuits/vote/          Noir circuit + inline test
contracts/              MembershipNFT, VoterRegistry, AnonVoting
contracts/verifier/     HonkVerifier.sol — GENERATED by bb, committed
script/Deploy.s.sol     deploy + wire + mint badges
test/                   forge tests; test/fixtures/vote-proof.json is generated
js/                     member client: join, propose, vote, tally, demo
NOTES.md                the end-to-end flow and the threat model
```

Generated and gitignored: `node_modules/`, `out/`, `cache/`, `broadcast/`,
`circuits/vote/target/`, `deployments/`, and **`notes/`** — which holds voter secrets and must
never be committed or shared.

## Known limits

Summarised here, argued properly in [NOTES.md §5](./NOTES.md):

- The running tally is visible in calldata before the deadline; `tally()` gates only the
  official read. Hiding it fully needs threshold encryption and a decryption committee, which
  reintroduces a trusted party.
- Anonymity is bounded by the electorate snapshotted at proposal creation, not by turnout.
- The relayer must not be operated by, or reachable in an identifying way from, the DAO —
  otherwise the operator sees what the chain does not.
- Secrets derive from a wallet signature, so compromising that signature de-anonymises that
  member's entire voting history retroactively.
