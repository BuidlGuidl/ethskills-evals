# Aerodrome USDC/WETH Yield Vault — Design

Vault on Base. Users deposit, vault LPs into Aerodrome USDC/WETH, **stakes the LP in the pool's gauge**, keeper calls `harvest()` to compound.

## TL;DR

- Staked LP earns **AERO emissions only**. It does **not** earn swap fees.
- `harvest()` claims AERO from the **Gauge** (`gauge.getReward(address(this))`). Nothing to claim from the pool.
- Swap fees generated by the vault's liquidity go to **veAERO voters** who voted for this pool, not to the vault.

## 1. Background: how Aerodrome pays LPs

Aerodrome is a ve(3,3) DEX (Velodrome fork). Each pool has a choice for LPs:

| LP state | Earns swap fees | Earns AERO emissions |
|---|---|---|
| Unstaked (LP tokens in wallet) | Yes (`pool.claimFees()`) | No |
| Staked in gauge | **No** | Yes (`gauge.getReward()`) |

When LP tokens sit in the gauge, the fees on that liquidity are claimed by the gauge and pushed to the pool's `FeesVotingReward` contract. veAERO holders who voted for the pool claim them there, pro rata to votes. That is the "fees to voters" trade in ve(3,3): LPs get emissions, voters get fees + bribes.

Emissions per gauge are set weekly by veAERO votes. Epochs flip Thursday 00:00 UTC; the gauge's AERO is streamed linearly over the following 7 days.

## 2. Pool choice

Two USDC/WETH options on Aerodrome:

- **vAMM-WETH/USDC** (classic volatile pool, `x*y=k`). Fungible ERC20 LP, `Gauge`. Simple, no range management. **Recommended for v1.**
- **Slipstream CL pools** (concentrated liquidity, NFT positions, `CLGauge`). More emissions per $ when in range, but zero emissions when out of range → needs a rebalancing keeper, much more complex. Out of scope for v1.

The rest of this doc assumes vAMM. Slipstream differences noted where relevant.

## 4. Deposit / withdraw

**Deposit:** take USDC (or USDC+WETH) → swap to ~50/50 by value → `router.addLiquidity(USDC, WETH, false, ...)` with min amounts → `gauge.deposit(lpAmount)` → mint ERC-4626 shares.

**Withdraw:** burn shares → `gauge.withdraw(lp)` → `router.removeLiquidity(...)` → return tokens (optionally swap to one asset).

Invariant: vault holds ~0 idle LP; all LP is in the gauge.

## 5. `harvest()` flow

```
keeper → Vault.harvest(minOut...)
  1. gauge.getReward(address(this))        // claims AERO from the Gauge
  2. take performance fee in AERO → treasury
  3. swap AERO → USDC / WETH (split ~50/50) via Router, with minOut
  4. router.addLiquidity(USDC, WETH, false, ...) with min amounts
  5. gauge.deposit(newLp)
  6. emit Harvest(aeroClaimed, lpAdded, fee)
```

Details:

- **What:** AERO only. Single reward token.
- **From where:** the pool's `Gauge` contract. Not the pool, not the Voter, not `FeesVotingReward`.
- **Who can call `getReward`:** Gauge checks `msg.sender == _account || msg.sender == voter`. So the keeper cannot claim for the vault directly; the vault must call it. Keeper just triggers `Vault.harvest()`.
- **No `pool.claimFees()` call.** With all LP staked, the vault has no fee claim on the pool. Calling it returns ~0 and wastes gas.
- **Slipstream variant:** `CLGauge.getReward(tokenId)`, still AERO only; compounding = `increaseLiquidity` on the staked NFT.

### Harvest safety

- Swap slippage: keeper passes `minOut` computed off-chain; contract also checks against a TWAP / Chainlink bound. AERO→USDC is sandwichable otherwise.
- Access: `harvest()` restricted to keeper role (or public with minOut sanity bounds).
- Skip if claimable AERO < threshold (`gauge.earned(address(this))`).
- Dust from uneven `addLiquidity` stays in vault and is included in next harvest.
- Frequency: Base gas is cheap, but AERO swap price impact matters more. Daily is a sane default; tune by TVL.

## 6. What the position earns (realistic)

### Gross

```
emissionAPR = (AERO to gauge this epoch × AERO price × 52) / TVL staked in gauge
```

- Only **staked** TVL counts in the denominator, not total pool TVL.
- Changes every Thursday with votes. Can move a lot week to week. Check live on aerodrome.finance / on-chain (`gauge.rewardRate()`, `gauge.totalSupply()`); don't hardcode a number in docs or UI.
- Swap fees: **0** to the vault (see §7).

### Nets against

| Item | Effect |
|---|---|
| Impermanent loss | USDC/WETH is volatile; IL vs holding 50/50 is the main risk. A 2x ETH move ≈ 5.7% IL. Emissions must outrun it. |
| AERO price | Rewards are paid in AERO and sold immediately. Constant sell pressure from all farmers; AERO price drop lowers realized APR. |
| AERO→USDC/WETH slippage | Price impact on each harvest sell. |
| Performance fee | e.g. 10% of harvested AERO. |
| Keeper gas | Small on Base, but nonzero; matters at low TVL. |
| Compounding | Adds a bit (daily compounding of APR r ≈ e^r − 1 APY). Minor vs. the above. |

### Honest summary

`net ≈ emissionAPR × (1 − perfFee) − sell slippage − IL − gas`

Headline APR is emission-driven and variable. In a trending ETH market IL can wipe it out; in a ranging market the vault does well. Show users the emission APR as "variable, paid in AERO, before IL" — not as a fixed yield.

## 7. Where the swap fees go

1. Traders pay the pool fee on each swap (vAMM default ~0.3%, set per pool by factory).
2. Fees accrue to LP token holders. The vault's LP is held by the **Gauge**, so the Gauge's share accrues to the Gauge.
3. On each epoch's `notifyRewardAmount`, the Gauge calls `pool.claimFees()` and sends the tokens (USDC + WETH) to the pool's **`FeesVotingReward`** contract.
4. veAERO holders who voted for USDC/WETH that epoch claim them next epoch, pro rata to their votes.

**Net: vault's LPs get none of the swap fees.** They are the "price" paid for AERO emissions.

### If we want fees back (future options)

- **Don't stake:** earn fees via `pool.claimFees()` (USDC + WETH), no AERO. Lower yield typically, no AERO price risk. Could be a separate "fee-only" vault.
- **Lock AERO → veAERO and vote for our own pool:** vault receives a share of fees + bribes and boosts its own emissions. Adds lock (up to 4y), vote management each epoch, and much more complexity. Not v1.
