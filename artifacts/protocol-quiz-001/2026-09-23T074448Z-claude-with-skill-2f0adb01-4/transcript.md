Written to `answer.md`. The short version:

**Build on EIP-1186 hexary MPT proofs today, verified against a state root from the beacon light-client sync protocol — with the commitment scheme behind a versioned, swappable module.**

Where the state layer actually is:

- **Verkle is off the table.** EIP-6800 is `Stagnant`, untouched since 2023. It lost on post-quantum grounds (elliptic-curve commitments, vs. the EF's Dec-2029 quantum-resistant-L1 commitment) and SNARK-friendliness. Any roadmap material still pointing at Verkle is stale.
- **The direction is a hash-based binary tree**, and it has converged: EIP-7864 → **EIP-8297 "Partitioned Binary Tree"** (Draft, June 2026, Buterin/Ballet/Feist et al.) plus **EIP-8347** for migration. Differential devnets exist; Erigon and Geth are tracking it.
- **But nothing is scheduled.** Glamsterdam (Q4 2026, Sepolia Oct 6) is ePBS + BALs. Hegotá's must-ship set per the EF tier list of Sept 7 is FOCIL and Frame Transactions; 8297/8347 aren't in that list at all, and the priorities post says the state arc's major work "is expected to begin in **I\***" — post-Hegotá, realistically 2028+, and "begins" ≠ "activates."

The timing caveat that matters: 8297 is Draft, not CFI or SFI for any fork — two status steps short of "it's in" — and its hash function is openly undecided (BLAKE3 today, Keccak/Poseidon2 still live). So don't build against PBT specifics now; build so the port is a release, not a rewrite.

The four things EIP-8347 breaks that people hardcode: `storage_root` disappears entirely (the two-level account→storage proof collapses into one tree), key derivation changes to zone/prefix-free keys, the hash is a parameter not a constant, and the swap is a clean fork boundary with no dual-root overlay — so an immutable on-chain MPT verifier is a liability. Trigger to start the port: 8297 reaching CFI for a named fork.
