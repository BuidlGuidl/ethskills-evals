Written to `answer.md`. Short version: **The plan is unsafe — don't ship it.** The CREATE2 reasoning is wrong for v4 specifically. **Why it must fail, by arithmetic:** CREATE2 gives the same address only when deployer, salt, *and init-code hash* all match. `PoolManager`'s constructor is `constructor(address initialOwner)` (v4-core `src/PoolManager.sol:101`), and I measured a different owner on each chain — mainnet `0x1a9C…35BC`, Base `0x31FA…72A9`, Arbitrum `0x2BAD…46CD`. Different constructor arg → different init code → necessarily different address. v3's factory took no such argument, which is where the belief comes from. **What I found probing the mainnet addresses on Base/Arbitrum (live, 2026-08-18, confirmed on a second RPC):** - PoolManager, StateView, Quoter — **no code** on either chain.
